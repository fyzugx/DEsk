# DEsk

> **DEsk**（デスク）は、**D**esktop **E**nvironment と **desk**（机）を掛け合わせた名前です。
> Reddit のコミュニティからの提案で生まれました。以前の名前は DeskWM です
> （コマンドは `desk`・`desk-session`・`desk-settings` などに変わりました。旧名の設定・データ・
> 環境変数 `DESKWM_*` はそのまま引き継がれます）。

**リアルなスキューモーフィズム**で作った、**Linux 向けの Wayland デスクトップ**です。
iOS 6 のころのように画面の中の物を本物そっくりに描く考え方で、デスクトップそのものを一つの机にしました。

窓はウォルナットの机に載った紙、ドックは引き出しです。アプリは机の奥の本棚のバインダーに綴じてあり、通知はポストに届き、システムの操作は机の奥に組み込まれた Control Panel でします。
部屋はレイトレースで描かれ、一つの電気スタンドがそのすべてを照らします。
フラットな懐古スキンではなく、ウォルナットの木目・引き出しのフェルト・紙の繊維・レザーのステッチをピクセル単位で組んでいます。

## インストール

[Releases のページ](https://github.com/fyzugx/DEsk/releases)から最新の版を落として展開し（このリポジトリを clone しても同じです）、そのフォルダで、使っているシステムの行を実行します。

**Debian 13**

```sh
sudo sh scripts/install_debian.sh
```

**Ubuntu 24.04 / 26.04**（Linux Mint、Pop!_OS も）

```sh
sudo sh scripts/install_ubuntu.sh
```

**Arch Linux**（EndeavourOS、Manjaro も）

```sh
sudo sh scripts/install_arch.sh
```

**Fedora 43 / 44**（Nobara も）

```sh
sudo sh scripts/install_fedora.sh
```

終わったらログアウトして、ログイン画面で **DEsk** を選びます。

**NixOS**：コミュニティが保守する flake が `packaging/nix` にあります。システムへの加え方はその README に。

- 入れるものを見せて、先に聞きます。`--yes` で、すすめる答えのまま進みます。`--no-apps` なら、おすすめのプログラムは入れず DEsk だけにします。
- 最初のログインで一度だけ部屋を描きます。GPU なら数秒、無ければもう少しかかります。次からはすぐに始まります。
- 更新は、新しい版を落として同じ行をもう一度実行するだけです。設定は残ります。
- 消すときは、DEsk からログアウトしてほかのデスクトップで `sudo sh scripts/uninstall.sh`（下の「インストール（Wayland セッション）」に詳しく）。
- うまくいかないときは、下の「困ったとき」と「不具合を知らせるとき」へ。

オプションや、自分でビルドする方法、窓の中で動かす方法は、下の「インストール（Wayland セッション）」と「ビルド」にあります。

## 見た目 — 本物がそこにあるように

画面の中の物は、机の上の物を記号にした絵ではありません。iOS 6 のころのリアルなスキューモーフィズムと同じく、
**本物の物がそこに置かれているように見えること**を目指して、素材の質感・光・影・使い込んだ跡まで描いています。

- **机**：オイル仕上げのウォルナットの天板。年輪・節・導管に、ニスに映る電気スタンドの光
- **時計**：机の上に置いた、赤い LED のデジタル時計
- **窓**：クリーム色の紙。繊維と裁ち落としの厚みがあり、右上の折れた角の裏に Fold / Unfold / Discard
- **最小化**：封筒のように縦、横と折りたたみ、紙束として机の上に置く
- **ドック**：机の引き出し。フェルトの内張りと真鍮のカップ取っ手。取っ手か Super+D で開け閉め
- **引き出しの中**：入れたものが横一列に並ぶ。最初は机の引き出しにありそうな小物
  （ポケットコンピュータ、真鍮の方位磁針、マニラフォルダ、メモ帳と鉛筆、ドライバー）。
  どのアプリも、最小化した紙も入れられる（下の「引き出しの中身」）
- **本棚の下の段**：木の置き時計・卓上カレンダー（付箋を貼れます）・メモ帳
- **ほかのアプリ**（Thunar・Caja など）も、DEsk の**アイコン**と **GTK テーマ**で同じように
  本物らしく（下の「アプリのアイコンとテーマ」）

### アプリのアイコンとテーマ

DEsk のセッションでは、ほかのアプリも机に合わせた見た目になります。

- **アイコン「DEsk」**（`themes/icons/DEsk`、`themes/make-icons.py` で描いた SVG）：
  iOS 6 のころのように、**本物がそのまま置かれたような**絵です。紙・厚紙・木・
  ヘアラインの金属の地肌、縁に当たる光、型押しのくぼみ、机に落ちる影まで描いています。
  - 場所：中に書類の入ったマニラの厚紙フォルダ（ドキュメント・ダウンロード・音楽・
    写真・動画・テンプレート・公開・リモート・最近は表に型押しの印）、家（ホーム）、
    胡桃材の机に紙と鉛筆（デスクトップ）、向こう側まで透ける金網のくずかご（いっぱい
    だと丸めた紙）、真鍮の台の地球儀（ネットワーク）、胡桃材の箱に緑の画面
    （コンピュータ）、アルミのドライブ、胡桃材の USB メモリ、虹色に光るディスク、
    フロッピー、メモリカード。
  - ファイル：角の折れた紙にタイプした文字（テキスト）、レターヘッドと青インクの
    署名の手紙（文書）、緑の罫の帳簿（表）、マウントに入ったスライド（プレゼン）、
    赤い判子の押された紙（PDF）、緑の縞の連続用紙に打ち出したプログラム（スクリプト）、
    印刷したウェブページ（HTML）、インスタント写真（画像）、ジャケットから出かけた
    レコード（音楽）、カチンコ（動画）、テープで封をした段ボール箱（圧縮ファイル）、
    パンチカードの束（実行ファイル）、インクの付いた木活字の A（フォント）。
  16〜31 px 用には、地肌や細かい印刷を省いて縁を太くした版を別に持っています。
  形と光はグラデーションで描き、地肌や影は SVG のフィルタで足しているので、フィルタを
  描かない Qt のアプリでも同じ物に見えます。無いもの（ツールバーの矢印など）は Adwaita
  から。
- **GTK テーマ「DEsk」**（`themes/gtk/DEsk`）：Adwaita の上に、窓は紙の色、リストや
  文字欄は白い紙、文字はインク、選んだものは真鍮、メニューバーとツールバーはマニラの色。
  Qt のアプリも GTK に合わせて着替えます（qt6-gtk-platformtheme）。
- **GTK 4 のアプリ**も同じ色に（`gtk-4.0`：GTK 4 の標準のテーマの上に重ねる。GitHub #17
  で VKOWinHecker201 さんが作ってくれたもの）。ただし libadwaita で作られたアプリ
  （Nautilus・電卓など GNOME のほとんど）はテーマを見ないので、そのままです。それらも
  紙の色にしたいときは、`~/.config/gtk-4.0/gtk.css` に次の 1 行を書きます（ほかの
  デスクトップでも効きます。やめるときはその行を消します）：
  `@import url("file:///usr/local/share/themes/DEsk/gtk-4.0/paper.css");`
  （`--prefix` を変えて入れたなら、その下の `share/themes`）
- **DEsk のセッションの中だけ**：desk-session が dconf に DEsk 用の層
  （`desk-dconf-profile`：DEsk の層をユーザーの設定の上に重ねる）を使わせ、最初の
  ログインでその層にアイコンと GTK テーマを入れます。GNOME など、同じ機械のほかの
  デスクトップの見た目は変わりません。DEsk の中で nwg-look などで変えた見た目も DEsk の
  中だけに残ります。X で動く GTK アプリ（Caja・Pluma など MATE のもの）は設定デーモンの
  無いところでは `~/.config/gtk-3.0/settings.ini` を見るので、そこにアイコンとテーマの
  名前が無ければ書き足します（GNOME や Xfce は設定デーモンが先なので影響しません）。
  `DESK_LOOK=0` で何もしません。元の見た目に戻すには、DEsk の中で nwg-look（Shell
  Settings の Look of other programs）から選び直します。

## 部屋

デスクトップは 1 枚の絵ではなく、**ひとつの 3D シーン**です。床・壁・幅木・机・
引き出しが同じ SDF シーンに入っていて、カメラも光源も 1 つ（引き出しの中身だけは、
置いた所に描いて重ねます。下の「引き出しの中身」）。

- **真上からの平面図** — 2D 版と同じ構図です。机が画面いっぱいに広がり、
  引き出しが下に出る。シーンは 3D で、見え方が平面図というだけです。
  真下を向くと通常の上方向がカメラ軸と平行になるので、画面の上は「奥」に取ってあります
- **光源は軸から外して**あります。真上から見て真上に光を置くと、天板が光源の鏡像を
  画面いっぱいに返して真っ白に飛びます。手前上方に吊ってあるので、影は奥へ伸びます
- **引き出しは机から手前へ**引き出され、開いた中が見下ろせます
- 影・環境光・被写界深度・ACES・ブルームはレイトレーサが解きます。
  面ごとにグラデーションを足して立体を装う作業はもう要りません
- 当たり判定はトレーサが出す **ID バッファ**を引きます。透視投影された物は、矩形では
  表現できません。引き出しの中身だけは置き場所が決まっていないので、フェルトの上の列の
  座標で引きます（`desk_drawer_at`）
- 部屋は静物なので一度焼いてキャッシュします（`~/.cache/desk/room-*`）。
  焼き上がるまではコンポジタは無地の机を出し、焼けたら差し替えるので起動は止まりません。
  **机だけ先に焼いて先に出します**（下記）

ウィンドウだけは 3D にしていません。3D 空間の板に貼ると文字が斜めになって読みにくく、
入力の逆投影とリアルタイム描画のために GL の自前レンダラが必要になるためです。
ウィンドウは画面座標の矩形のまま、机の上に置かれます。

### 引き出しとカメラ

部屋は**2 枚のシート**として焼かれます。ひとつは引き出しの空いた部屋、もうひとつは
空の引き出しだけを目一杯引き出した状態。どちらも同じカメラで焼いてあるので、重ねてずらせば
開閉になります。中身は 3 枚目（下の「引き出しの中身」）。1440x900 の 2 枚を焼くのに 6.8 秒かかる以上、開閉をリアルタイムにする方法は
これしかありません。実行時はシーンノードを動かすだけで、毎フレームの描画コストはゼロです。

## All Apps — 本棚

机の奥、**ポストの右隣に小さな真鍮板**が留めてあります。刻んであるのは `ALL APPS ↑`
だけで、`CONTROL PANEL ↑`・`POST ↑` と並ぶ三枚目の札です。機械に付いている銘板と
同じで、操作盤ではなく札です。ポストと画面の端のあいだに収まる大きさで、隙間が狭い
画面では小さくなります（以前は右の縁に縦に留めてあり、帯から下へ長くはみ出して、
窓の邪魔になっていました）。これをクリックするか `Super+A` で、
**カメラが机から持ち上がって背後の本棚を見上げます**。座り直すので引き出しは閉まります。

カメラの動きは**実際にトレースしたフリップブック**です。平面図として焼いたシートを
アフィン変換しても仰角の変化は表現できず、両端をクロスフェードすると「カメラが動いた」
ではなく「ディゾルブした」に見えます。そこで解像度 1/4 で 18 コマ焼いてあります。
両端もコマなので、どちらの端にも飛び越える隙間がありません。

再生時は**2 枚のシーンノードに掛けて隣り合うコマを重ね、不透明度で混ぜます**。1 コマの
コストはソース矩形 2 つと不透明度 1 つ。cairo も確保も走りません。毎フレーム全画面
バッファを描き直していたときは、これがそのままカクつきでした。緩急は smootherstep
（両端で加速度が 0）で再生側に掛けてあり、焼いたコマの間隔は等間隔です。二重に曲げても
滑らかにはなりません。

見上げたとき、手前には机があります。その背の縁に組み込まれた Control Panel と
ポストは**そこからも触れます** — クリックすると一度机へ降りて、それからそちらへ
向き直ります。首がやることをそのままやっているだけです。

本棚は机と同じ木で、蝋引き。8 冊のバインダーが仕切りを挟んで**上の段**に一列に
並び、その**右端に紺の革装の本が一冊**立っています（全部のアプリの索引。後述）。Control Panel とポストは机の背の縁に組み込まれていて、見上げるとその段の
前に立つ — 立っていて構わない（机の物の向こうに本棚があるのが見上げる意味です）
のですが、**読みに来た一列の前に立たれては困る**ので、バインダーは上の段です。

**下の段には、メモ・カレンダー・時計が台座に載って立っています。** 机の上に寝かせて
あったものです。机は作業面で、これらは横目で見るものではなく**見上げるもの**なので、
棚に上がりました。机に残したのは奥の時計だけで、これはシステム
トレイの扱いです。

上の板の下には**小さな真鍮の灯りが二つ**、棚ごとに一つずつ付いています。部屋の灯りは
机の上にあって本棚のずっと手前なので、そこに立っているものは目の寛容さだけで読めて
いました。この二つは**影を落としません** — この部屋で影の線を引く灯りは一つだけで、
これはそれではない。下に置いたものを読めるようにするためだけの灯りに、標本ごとの
影線をもう一本引かせると焼き時間が四割増えます。

背表紙のラベルは**焼き込みではなく毎フレーム cairo で刷っています**。だから
`apt install` しても本棚を焼き直さずに中身と冊数が変わります。

ポインタを載せたバインダーは**列から手前へ出てきます**。棚から本を半分引き出して、
持っていくか決めるときの動きです。背表紙のピクセルを案内図から切り出し、抜けたところを
暗くして、切り出しを少し大きく・少し下に描き直す。上前方にあるカメラにとって、
それが「手前に出てくる」の見え方です。

バインダーをクリックすると、**右端の本と同じように棚から抜いて、手元で回して開きます**。
背のラベルを見せたまま棚から抜け、縦の軸で回って表紙がこちらを向き（棚の背と同じ
牛革の赤か緑のクロスに、ぐるりとステッチ、分類名の空押し）、表紙が背を軸に起き上がって
左へ倒れます。紙は閉じている間は板の上に揃った束で、表紙が上がると手を離した紙のように
前の紙から順にゆっくり落ち始め、少し行き過ぎて戻り、リングから扇に垂れます。開いたバインダーの板も、棚の背と同じ色です
（以前は分類ごとに別の色で、棚から取ると色が変わっていました）。棚には**抜けた暗い隙間**が
残ります。開いたバインダーは正面からの絵ではなく、机に下端を付けて**少し回して
後ろへ倒して**持っています（卓上カレンダーと同じ描き方）。奥の側が小さく、表紙の板の縁が
見え、下の方がわずかに暗くなります。紙の指し方・角のめくり・取り出しは、傾いた面の上の
位置をそのまま読み取ります。紙は**リングひとつ**から重力で扇状に垂れる — リング3つは紙束を固定してしまい、
固定された束は何も見せてくれません。手前の1枚は原寸で読め、後ろの数枚は**柱脚**（下端の
余白に刷った名前とカタログ番号）が見えます。

**ホイールで紙が動きます**。1ノッチ＝1枚。ただし**ひと撫でで5枚まで**。トラックパッドの
1フリックは15単位のノッチが20発以上まとめて届くので、1発1枚だと束を最後まで
めくり切って端に張り付きます（それが「回らない」の正体でした）。時間で律速しても
区別できません — コンポジタがそのノッチを1フレームに1発ずつ均してしまうからです。
なので**ジェスチャ単位で数えます**。届き続けるノッチは同じひと押しで、ひと押しは
数枚めくる。0.25秒静かになればジェスチャは終わりなので、1ノッチずつの操作は制限されません。束の位置は小数で持っているので、繰りは飛ぶのでは
なく動きます — 手前の紙が**リングを軸に上へ回り込み**、向こうへ抜けながら薄れて、次の紙が
出てきます。数度よけるだけでは「一覧がスクロールした」に見えるので、ちゃんと 60 度回します。
最後の1枚まで繰れます。矢印キーも1枚ずつ、PageUp / PageDown で扇ひとつ分。

紙をクリックするとアプリが起動し、**その紙を手に取って机へ置きます**。

1. 紙がリングから外れて手に持ち上がります（少し大きくなり、影が離れて薄くなる）。
   バインダーは開いたまま、棚が見えなくなってから棚へ戻します
2. 紙を持ったまま机へ向き直ります。紙は窓が出る場所の上まで運ばれ、
   視点が机に着くのと同時に下ろされます（影が寄って濃くなる）
3. 置いた紙の後ろから紙が出てきて（窓の大きさを変えるときと同じ、折り目の残った紙）、
   窓の大きさまで広がり、カタログの印刷が消えます。残るのは、頭にアプリ名だけが
   刷られた白紙 — **窓の土台**です
4. アプリの窓が来ると、土台の上にそのまま乗って、土台は消えます。窓が紙を置くより
   先に来たときは、紙が置かれて広がるまで待たせます（その場合、土台はその窓の
   大きさまで広がります）。45 秒たっても窓が来なければ、土台は丸めて捨てます

アプリの窓は、そのアプリの紙の土台に乗ります（.desktop の id・StartupWMClass で
照合）。自分が何のアプリかを言わない窓は、最近置いた土台が一つだけのときだけそこへ。
ダイアログやスプラッシュは土台に乗りません。

### 右端の本 — ALL APPS の索引と検索

バインダーは分類ごとなので、名前は知っていても**どの棚に入っているか分からない**ものは
探せません。そこで一列の右端に、全部のアプリを A から Z に並べた**索引の本**を一冊
立てました。紺のモロッコ革に金の背バンド、背には赤い題箋に `ALL APPS`、虫眼鏡、`A–Z`、
冊数。背の文字は焼き込みではなく毎フレーム刷るので、アプリが増えれば数も変わります。
本の形（背の丸み、天の小口、金の箔、5 本のバンド）は部屋と一緒にトレースしていて、
GPU 版（room.glsl）も同じ形です。4:3 の画面では右端に場所が無いので、棚の方を広げます。

ポインタを載せると他のバインダーと同じく手前へ出てきます。クリックすると、
**棚から抜いた本を手元で回して、表紙を開きます**。

1. 背を見せたまま棚から抜け、手前へ来ます（棚の上の、部屋の暗めの光から、手元の
   灯りの中へ）
2. 縦の軸で回って、**表紙がこちらを向きます**。紺の革に金の二重罫と四隅の花、
   `ALL APPS`、`AN INDEX OF EVERY PROGRAM`、虫眼鏡、`A–Z`、冊数を金で押してあります。
   回っている間は背と表紙の両方が見え、背の金の模様は丸みに沿って回ります
3. 表紙が背を軸に起き上がって向こうへ倒れ、裏に最初のページ（題と書く行）を
   乗せたまま左に寝ます。ページの束はそのあいだに平らになり、本は綴じ目が真ん中に
   来るよう横へずれて、少し後ろへ倒した持ち方（手帳やバインダーと同じ）に落ち着きます

本は箱として描いています：裏表紙、金の小口のページの束、丸い背、背で綴じた表紙。
面ごとに目の方を向いているものだけを、遠いものから描きます。開いた後の絵と同じ絵を
綴じ目で切って使うので、開き切った最後のコマは持った本そのものです。棚に戻すときは
同じ動きを逆に（表紙を閉じ、回して背を向け、棚の隙間へ）。最初のコマで使う絵は、
ポインタを本に載せている間に一枚ずつ先に刷っておきます。

- **左ページの頭に書く行**があり、開いた時点でもう**キャレットがそこにあります**。
  そのまま打てば絞り込まれます。名前の頭 → 単語の頭 → 名前の途中 → 総称・キーワード・
  id の順に並び、一番上が選ばれた状態（蛍光ペン）になります。**Enter で起動**。
  日本語の名前は、翻訳前の名前（`Name=`）と `Keywords=` でも引けるので、「けいさん」→
  「計算」で電卓、`term` で端末が出ます。入力メソッド（IBus）を通るので、変換中の文字は
  下線付きで行に書かれ、候補は手帳と同じ紙片に出ます
- 何も書いていないときは**索引**です。頭文字ごとに赤い見出し、行には アイコン・名前・
  総称・点線・入っているバインダー名。柱には見開きの文字の範囲（`A – D`）
- 小口には**爪掛けのインデックス**（A〜Z と #）が切ってあり、クリックでその文字の見開きへ。
  今いる文字は金、何も無い文字は薄く
- 絞り込んで結果が左ページに収まると、**右ページには選んだもの（ポインタの下のもの）の
  票**が貼られます。大きなアイコン、名前、翻訳前の名前と総称、入っているバインダーと
  その中での番号（`UTI · 012` — バインダーの紙の柱と同じ番号）、ほかに引ける言葉
- ホイール・PageUp / PageDown で見開きをめくります（紙が一枚、のどを軸に回ります）。
  ↑↓ で選ぶ行が動き、ページの外へ出ればそこまでめくれます
- 行をクリック（または Enter）すると、バインダーの紙と同じく**その行から紙が一枚
  持ち上がり**、机へ運ばれて窓の土台になります。本は開いたまま机へ向き直り、
  棚が見えなくなってから棚へ戻します（目を離した間に片付けたように）
- Esc は一度目で書いたものを消し、二度目で本を棚に戻します。本の外をクリックしても戻ります
- 開いた本は、**変わる所だけを描き直します**。めくるときは回っている一枚だけを描き、
  その下の見開きは止まった絵を使います（次にどちらへめくっても要る絵は、手を止めて
  いる間に一枚ずつ先に刷っておきます）。行や爪掛けにポインタを載せたときは、その行と
  爪掛け（と、右ページの票）だけを本の絵と同じ画素に継ぎ当てます。以前はめくる 1 コマが
  40 ms を超え、ポインタが行を移るたびに本全体（25〜30 ms）を描き直していました

### 紙が「升目の中のアイコン」に見えない理由

刷りむらです。印刷のかたまり全体が紙に対して少し芯がずれ、わずかに斜めに入っている。
一度濃く、一度うすく版がずれて二度打ちされている。名前を横切ってインクが切れている。
**紙に対して直角でない活字は、升目のセルには見えません。**
そのうえでパンチ穴、リングから外したときの裂け、小口の手垢、めくり癖のついた角。

### アプリはどこから来るか

実際にインストールされているものです。XDG のアプリケーションディレクトリを走査し、
menu spec の規則どおりに — 近いディレクトリが id を勝ち取り、隠された項目は id を
保持して遠いディレクトリからの復活を防ぐ — 8 つの棚に配ります。`Name[ja]` も読みます。
この機械では 856 ファイルから 106 本、0.46 秒。

`desk-preview --apps` で何がどの棚に入ったかを画素なしで確認できます。
`$XDG_CONFIG_HOME/desk/shelves.conf` に `org.kde.kate.desktop = Development` の形で
書けば、規則より優先されます。

アイコンが SVG しかない場合は cairo が読めないので、rsvg-convert（インストーラが入れます。
無ければ ImageMagick）で一度だけラスタライズしてキャッシュします。どちらも無ければ紙には
**活字の頭文字**が刷られます。

**閉じているときは天板が画面いっぱい**になります。机の奥行きはデスクトップの縦横比から
決めてあるので（`room_set_aspect`）、天板の比が画面の比と一致し、引き出しが閉じていれば
床も壁も視界から外れます。引き出しが出てくると、机が引き出しの高さだけ持ち上がって
引き出しと床が入ってきます。机の上の窓や紙も一緒に上がります。

### 机の上のもの

机の時計（システムトレイを兼ねる。下の「時計」の節）は、画面上のバーや貼り込みではなく
**机の上に置かれた立体**です（革の置き時計・カレンダー・メモ帳は本棚の下の段へ移りました）。本体（ベークライト、革、クロームのベゼル、紙）は部屋と
一緒にレイトレースされ、**面の中身だけ**を、窓が投影された矩形に 2D で描き込みます
（時計の針、カレンダーの日付、LED の数字）。真上から見ているのでその矩形はほぼ素直な
長方形になり、時刻が変わっても部屋を焼き直す必要がありません。

ウィンドウは机の上に置かれるので、これらの上に重なります。

## Control Panel — 机の左奥に組み込まれた機械

設定画面ではありません。**机の左奥の縁に組み込まれている一台の機械**です。真鍮の
金具、黒のちぢみ塗装の鋼板、ガラス、くるみの頬木。大型のままですが、**普段は机の
上にいません**。

机の主役は中央の作業スペースと紙のウィンドウです。この大きさの装置が出しっぱなしに
なっていると、机はその装置のものになります。だから机の**背の縁から出入りするスライド**
に載っています。しまってあるとき、線の上に残っているのは

- `CONTROL PANEL ↑` の真鍮プレート（銘の分だけの長さ）
- 前縁のパイロットランプ
- パネルの縁
- その下に挟まった、システムトレイの紙片

だけ。**隠しているのは机自身の遠端**です。上から見下ろすカメラでは天板の遠端より
向こうは一画素も見えない — 背後に六フィートの本棚が立っていても机の絵に影響しないのと
同じ仕組み（`room_hidden_z`）で、機械もそこに引っ込んでいます。引っ込みしろは画面の
縦横比から逆算します。遠端の位置は比で動くので、固定値だと 16:10 では出したまま、
4:3 では埋まってしまいます。

さらに、**遠端より奥にある部分はそもそも描いていません**（`map_console` の最後の一行）。
これが無いと、しまった機械は机の裏の虚空に浮き、壁を突き抜けます。真上からは両方とも
見えませんが、カメラが傾き始めた瞬間に見えます。遠端で切ってあるので、機械がするのは
**机の背の縁から出てくる**ことになります。

プレートかパネルの縁をクリックすると、ポップアップはしません。**機械が先に出てきて、
それからカメラが向き直ります**（スライドは移動の 46% で出切る）。順番が逆だと、
カメラが縁ぞいを見通せるようになった時にまだ機械が奥にいます。着いてから**球が
温まります** — ランプが順に点り、針が止まり木から上がり、ブラウン管に輝線が立つ。
バルブ式の装置は「点く」のではなく「回ってくる」ものです。戻るのは `Esc` か、
機械の外をクリック。

デスクライトも右手前へ移しました。大型の装置が部屋のいちばん明るい角にいると、
やはり机はその装置のものになります。いまは**光だまりが机の中央**にあり、左奥は
部屋でいちばん暗い場所です。

| 計器 | 何を指しているか |
| --- | --- |
| ブラウン管 | プロセッサの直近の履歴、メモリ、温度（下記） |
| BATTERY | 電池の残り。この機械には電池が無いので針は `LINE` を指します |
| 右のメーター | 既定経路の出ているインタフェース名、緑ランプ、最近の流量 |

| 操作子 | 動き |
| --- | --- |
| WIRELESS | レバーを投げる。倒れた側にランプが点く。塔の右上の**電動の伸縮アンテナ**が、80〜90 年代の車のラジオのアンテナのように、モーターの音とともに細い段から順に伸び（入）、太い段から順に縮みます（切）。ほとんどは画面の上へ出て行き、見えるのは根元の動き |
| BLUETOOTH | 金属のトグル。入れると青いパイロットランプ |
| VOLUME | **つまみを回す**。掴んだ手の角度にそのまま追従します（ホイールでも回ります）。真鍮の台座に 0〜10 の目盛りが刻んであり、現在値は**赤い ▲** が指します |
| LAMP（照明） | 溝の中のフェーダーを押す。机の上の明かり（部屋の照明）が落ちます |
| SCREEN（画面） | その下のもう一本のフェーダー。**画面そのもののバックライト**（ノート PC のパネル）を動かします（下） |

右の列のフェーダーは二本です。上が部屋の照明（LAMP）、下が画面の明かり（SCREEN）。
SCREEN のために機械は**左へ一列ぶん広く**なり（約 15%）、計器とつまみはその幅に
並べ直してあります。机の上から見える真鍮プレートの位置は変わりません。画面の狭い
（4:3 など）ときは、カメラが機械の両端まで入る所まで下がります。

**SCREEN** はバックライトのある機械（ノート PC）で動きます。`/sys/class/backlight` の
中から logind や他のデスクトップと同じ順（firmware → platform → raw）で一つ選び、
**logind の `SetBrightness`** で変えます（席にいるユーザーなら root でなくても変えられる
唯一の口です）。logind が無ければ、書き込める場合だけ sysfs のファイルへ直接書きます。
手を動かしている間は 40 ms ごとにまとめて送り、真っ暗にはしません（目盛りの最下端でも
1%）。キーボードの**明るさキー**（XF86MonBrightnessUp / Down）はどこにいても 1/16 ずつ
動かします。バックライトの無い機械（デスクトップ、仮想機）では、目盛りの代わりに
**`NO BACKLIGHT`（調光なし）** と刻まれ、つまみは上端で動きません。そのときの明るさキーは
LAMP を動かします。`DESK_SYSFS` に別の木を指せば、バックライトの無い機械でも試せます
（そのときは logind を通さず、その木のファイルへ書きます）。

### ブラウン管がブラウン管に見えるのは、緑だからではありません

**ビームが描いている**ように見えるかどうかです。

- **速いところは暗い。** 同じ電荷が広い蛍光面に散るので、波形の**急な斜面は細く淡く**、
  平らなところは太く明るく出ます。これ一つがいちばん効きます（`dwell`）。
- **消え残る。** 左端はいちばん昔に描かれた場所なので、そのぶん褪せています。
- **滲む。** 明るいところは隣へ漏れ、芯は緑を通り越して**白**になります。3 パス。
- **走査線**に櫛けずられ、**ガラスは瓶**なので画面全体が樽形に歪みます（`crt_warp`）。
- ハムで**明るさが呼吸**し、同期の外れた帯がゆっくり上へ流れます。
- 文字も蛍光面の上なので、印刷ではなく**滲んで**います。
- 暖まる途中は**一本の水平線から開いて**いきます。球はそういう点き方をします。

見た目を良くするためだけに 1 コアの 9% を足したので、**戻しました**。柔らかい 2 パスは
1 本のパスにして、褪せは区間ごとの描画ではなく画面に沿ったグラデーションに。走査線は
80 ストロークから 2 パスへ。ビームの速度が出る**芯だけ**が区間ごとです。220 ストローク
→ 50 ストローク、23% → 15%。

つまみのベークライトは台座よりだいぶ内側で止めてあります。目盛りには置き場所が要り、
台座いっぱいのつまみには環が残らないからです。なお**角度で変わる半径は距離場ではありません**
— 波打った縁までの本当の距離は素の円柱が返す値より短く（およそ `sqrt(1 + (Ak/R)²)` 倍）、
レイマーチャーが踏み越えて縁が虫食いになります。つまみを小さくすると同じ刻みが急になるので
悪化します。下界を渡せば止まります（`0.85 *`）。

**スライダーはひとつもありません。**すべて押す・引く・回す・倒すのいずれかです。
目盛りも針もつまみも、どこに描くかは**トレースした金物の寸法から計算**しています
（`RM_CC_SKIN`、`cc_face_size`、面ごとの `sx`/`sy`）。指針をつまみの直径から決めずに
面の何割かで決めていたときは、ベークライトの外へはみ出していました。

面の中身 — 針、輝線、ランプ、倒れたレバー、つまみの指針、フェーダーの握り — は
焼けません。動くからです。焼いたシートは一度だけ scene node に載せ、**上に重ねる
のは生きている半分だけ**にしてあります。

`desk-preview --console` で機械だけを書き出せます。

**スイッチのレバー、LAMP のつまみ、鍵は、パネルに刷った絵ではありません。** レバーは
ボスから手前へ突き出して ON か OFF の側へ倒れ（WIRELESS は黒いベークライトのバット、
BLUETOOTH は先に玉の付いたクロームのトグル）、LAMP のつまみは溝から立ち上がる角柱です。
どれも Control Panel のカメラで点ごとに投影し、面ごとに部屋のランプの当たり方で
明るさとつやを付け、ランプの光に沿ってパネルへ影を落とします。

### 電源 — 鍵と、ガラスの下の三つ

パネルの下段に、**このデスクトップを終わらせる唯一の場所**があります。

```
  [ SHUT DOWN ]  [ RESTART ]  [ LOG OUT ]      (ガラスの下)        ⌐o  ←鍵
```

**ひとつも一回のクリックでは押せません。**

1. 普段は**ガラスの蓋が下りていて、鍵がかかっています**。ボタンのランプは消えています。
   これは「放置されている」のではなく「切ってある」状態です。
2. 蓋の右に**鍵が寝ています**。クリックすると鍵は持ち上がり、起き上がりながら
   鍵穴の上へ運ばれて、穴に立ち、押し込まれ、そこから**勝手に 90 度回ります**
   （1.45 秒）。鍵は絵ではなく立体として描いていて、立った鍵の頭がパネルから手前へ
   突き出し、回ると鍵穴の筒（プラグ）も一緒に回ります。鍵が回りきると蓋の錠が外れ、
   三つのランプに**フィラメントが灯ります** — 赤 / 黄 / 緑。
3. **ガラスをクリックすると跳ね上がります**（エレベーターの非常ボタンの蓋と同じ形。
   無色透明で、三つ全部に被さっています）。上端で蝶番、真鍮の縁で持ち上げます。
4. ボタンを押すと、**そのランプがゆっくり暗くなります**。同時に部屋全体が暗くなり、
   **完全に真っ暗になった瞬間に初めて処理が走ります**（2.8 秒）。

最後の一押しだけは**取り消せません**。Esc も効きませんし、他のボタンも押せません。
鍵とガラスがそのためにあります。

実装の都合ではなく、世界の都合でこうなっています。真鍮・カバー・ランプはトレースに
入っていますが、**鍵とガラスは入っていません** — 動くものを焼くと、焼いた姿のまま
永久に止まるからです。ガラスは四隅を投影して塗り、鍵は面の中で描いています。

ランプの光だけは**プレートの明るさと別に**描いています。暗い部屋のランプは、その部屋で
いちばん暗いものではないので。

机に戻る（Esc / 机をクリック）と、**鍵は抜けて蓋は下ります**。開けっ放しの状態で
戻ってくることはありません。

三つとも、**まず開いている窓すべてに閉じるよう頼みます**（窓の閉じるボタンと同じ。
保存していない作業のあるアプリはここで聞いてきます）。最後の窓が閉じたら、ログアウト
（コンポジタが止まる）か、logind への `Reboot` / `PowerOff`
（`org.freedesktop.login1`）です。8 秒たっても閉じない窓（保存の確認、応えない
アプリ）があれば**止めます**：ランプを点け直し、机へ向き直って、その窓を前に出します。
60 秒以内にもう一度押すと、窓に 8 秒の時間をやった後、残っていても進みます。
`Super+Esc` / `Alt+Esc` も同じ流れでログアウトします。**logind に断られたら**
（polkit など）、真っ暗のまま放置せずにランプを点け直してログに出します。

### LOCK — 画面のロック

パネルの左下、ガラスの外に**青い LOCK（ロック）ボタン**があります。終わらせるもの
ではないので、鍵もガラスもありません。押すと、Control Panel の眺めのまま部屋から
**後ろ向きに玄関を出て**、ドアが閉まり、鍵を回して閉めます（画面ロックの、開ける
ときの逆）。開けると Control Panel の前に戻ります。

### プレートの右 — システムトレイ

```
  CONTROL PANEL ↑  |▯|▯|▯|
```

真鍮のプレートは**銘が刻める限界の長さ**まで詰めて（細身の字で、ねじも寄せて）、
本体の**左端**に寄せてあり、それを載せる台座の張り出しもそこで終わっています。その右は台座が本体の下まで下がっていて、机がそのまま見えます。
そこに**システムトレイの紙片**が、本体と机の間に挟まっています（下の「システムトレイ」の
節）。

以前ここにあった**回線の五つのランプ**は外しました。回線は Control Panel の右の
メーターで読めますし、ネットワークのアプレットがあればトレイの紙片にもなります。

## 動き — 机の上の物として

静止した物は、どれだけ丁寧に作っても机に貼り付いた絵に見えます。ここは造形ではなく
**挙動**の話です。

### カメラは引き出しと同じように動く

本棚・Control Panel・ポストへの視点移動は、引き出しと同じ減衰バネで動きます。すぐに
動き出し、加速して進み、目的地を **約 3% 行き過ぎて戻り**、止まります（ζ=0.74, ω=8.5）。
時間の 2 割で 6 割、半分で行き過ぎの頂点、9 割で元に戻ります。

```
        __/‾‾\___
   ___/              ←(1) すぐ動き出す  (2) 行く  (3) 行き過ぎる  (4) 収まる
```

以前はこの曲線に予備動作（最初に 4% 逆へ引く）まで入れていましたが、**画面には一定速度の
移動にしか見えていませんでした**。理由は曲線ではなく見せ方です。

- 視点移動はトレース済みの 18 コマの絵（フィルム）で、以前は隣り合う 2 コマを画面いっぱいに
  置いて**重ね合わせ（ディゾルブ）**ていました。コマ同士は移動の 6% ずつ離れているので、
  ゆっくり動く所（出だしと着地）は「動き」ではなく「じわっと切り替わるフェード」に見え、
  速い真ん中だけが一定速度で流れて見えていました。
- しかも目的地の手前 10% からは完成した静止画に切り替えていたので、行き過ぎて戻る部分は
  そもそも画面に出ていませんでした。出だしも、机の表示（机にズームした絵）とフィルムの
  1 コマ目の大きさが違い、フェードで誤魔化していました。

いまは、**各コマを「今のカメラ位置ならその部屋がどこに見えるか」に合わせてずらし・
拡大してから**重ねます（動き補償）。部屋の代わりに机の天板と奥の壁で格子状に光線を
飛ばし、コマのカメラと今のカメラでの位置から、コマを置く矩形を最小二乗で求めます。
ずらすだけなので GPU ではほぼ無料です。これで遅い所も速い所も「カメラが動いている」
ように見え、着地の行き過ぎと戻りは、仕上がった高解像度の絵ごと動かして見せます
（その縁から覗くのは机ではなく、下に敷いたフィルムの部屋です）。机に戻るときも同じで、
カメラは机を少し行き過ぎて戻り、机とその上の窓がそれに合わせて動いて止まります。出だしは机の表示と
同じズームから始まり、カメラが上がるにつれてズームを緩めます。

引き出しは手で掴んでいるので予備動作は無く、**止め板に当たって 1.5% のノック**が入ります
（ζ=0.80, ω=12）。バインダーを棚から机に下ろす動きも同じ曲線で、少し行き過ぎて着地します。
バインダーの紙をめくる動きは、目標に向かって速度を保ったまま追いかけるバネ
（ω=24, ζ=0.72）で、1 枚は約 0.2 秒、わずかに行き過ぎて他の紙に落ち着きます。
続けてめくると一つの流れになり、1 枚ごとに止まりません。

### 紙は平らではない

- **どの紙にも、下がらない角がひとつあります。** どちらの角かとどれくらいかは
  タイトルから引いた種で決まるので、紙の焼けや汚れと同じ種です。
- **影がそれを知っています。** 浮いた角の下には空気があるので影は遠くまで柔らかく伸び、
  机に付いている角では影は細く硬い線になります。紙と「ぼかしを敷いた長方形」の違いは
  ほぼこれだけです。
- **紙の縁が反ります。** 浮いた角に向かってランプの光を受けて明るくなり、
  反りの付け根に折り筋が入ります。見えるのは余白の部分だけですが、反りが出るのも
  そこです。
- **引きずるとたわみます。** 影は紙に剛体で付いてきません。動かすと後ろに残り、
  手を離すと**少し行き過ぎて**から追いつきます（減衰バネ）。
- **持ち上げると持ち上がります。** 掴んでいるあいだ影は遠ざかり、4.5% 広がり、
  22% 薄くなります。置くと戻ります。

### 棚の上の物

- **三つとも真っ直ぐ置かれていません。** メモ・カレンダー・時計にそれぞれ
  2〜3 度の**ヨー**が入っています。台は真っ直ぐなので、「人が置いた」に見えます。
- **秒針は針の動きをします。** 目盛りに到達するのではなく、**投げられて**約 0.1 秒で
  着き、行き過ぎて鳴いてから止まります（ζ=0.42, ω=13、行き過ぎ 23%）。
  これを見せるために、**本棚を見ているあいだだけ**棚の描画を毎秒 10 回にしています
  （普段は毎秒 1 回）。1 秒に 1 枚では投げも鳴きも無く、「さっきと違う時計の絵」に
  しかなりません。

### 卓上カレンダー

カレンダーは**机に立てる卓上カレンダー**です。革を張った 2 枚の台紙が三角に寄りかかり、
上の縁を黒いダブルリングが巻いて、月ごとのページがそこから下がっています。ページには
大きな月の数字、月の名前と年、日曜は赤・土曜は青の格子、**今日には赤ペンの丸**。
台紙もリングも紙の束も部屋の一部として光線追跡で焼いてあり（C と GPU の両方）、
今月のページはその上に刷ってあります。

- **クリックすると手に取ります。** 棚に一歩近づいてカレンダーを取る動きで、本棚の上の
  位置から画面の中央へ大きくなります。後ろの本棚は少し寄って見え、目がカレンダーに
  移るので軽くぼけます（暗くはなりません）。拡大したページには、前の月と次の月の小さな暦と、日付の横に
  書き込める升目。
- **手に取ったカレンダーは平らな絵ではありません。** 少し右へ回して後ろへ傾けて
  持っているので、奥の側が小さく、手前の側が大きく見え、横から台紙の三角
  （2 枚の台紙の縁と、その間の暗いテントの内側）と紙の束の厚みがのぞきます。
  棚の明かりを上から受けるので、下の方がわずかに暗くなります。手帳が横に来ると、
  カレンダーは手帳の方へ向き直ります（目が画面の中央にあるので、手帳側の縁が
  見えます）。手帳も同じで、カレンダーの方へ少し向けて持ち、リングは手帳から
  手前へ弧を描いて立ち上がっています。手帳は横から滑ってくるだけでなく、縁を
  見せるほど横を向いた所から正面へ向き直りながら入ってきます（帰るときは逆）。クリックは傾いた面の上の位置をそのまま
  読み取ります。
- **ページの足（下の端）をクリックすると次のページ**：今のページが下から持ち上がり、
  リングを越えて後ろへ回ります（裏から月の数字が透けて見えます）。**ページの頭（月の
  数字のあたりから上）をクリックすると前のページ**：後ろに回してあったページが、
  リングを越えて戻ってきます。日付のところは予定を書くのに使います（下）。
- **ポインタを載せた側の端が少し立ちます。** 足なら今のページの下端が持ち上がり、
  頭なら前のページがリングの上からのぞきます。指を掛けたときの紙の動きです。
- ホイール（下で次、上で前）、← → ↑ ↓、Page Up / Down でもめくれます。続けて
  めくると、前のページが下りきる前に次が行きます。
- **年・月・週・日の切り替え。** ページの束は 4 つの区分（年 → 月 → 週 → 日）が前から
  順に重なっていて、ページの右端からそれぞれの**札**が突き出しています（YEAR・MONTH・
  WEEK・DAY、色違いのカードに横向きの縦書き）。札をクリックすると、その区分までの
  紙が**束になって一度にリングを越えます**（束は少し扇に開き、紙の端が何枚も見える）。
  後ろの区分へ行くときは前の束が後ろへ、前の区分へ戻るときは後ろに回した束が戻って
  きます。後ろに回した区分の札は台紙の陰から少し短く見えていて、いつでも押せます。
  キーなら Y・M・W・D。
  - **年**：12 か月の小さな暦（今の月に印、今日に赤丸）。上下で前後の年。
  - **月**：今までのページ。上下で前後の月。
  - **週**：日曜から土曜の 7 列、曜日と日付と書き込む罫（第何週かと、何日から何日か）。
    上下で前後の週。
  - **日**：大きな日付と曜日、8 時から 20 時の時間の罫、NOTES と TO DO、その年の何日目か。
    上下で前後の日。
  開いていた区分は覚えていて、棚の上のカレンダーもその区分のページで立っています。
  年のページで月の名前をクリックすると、その月のページへ。

### 卓上メモ

カレンダーの左は**卓上メモ**です。カレンダーと同じ作り（革張りの台紙が二枚、上を
ダブルリング）で、少し縦長、月のページの代わりに**罫線の入ったクリーム色のメモ用紙**が
綴じてあります。棚の上では、いちばん上の紙に**書いてあることがそのまま見えます**。

- **クリックすると手に取ります。** カメラワークはカレンダーと同じです（本棚に一歩寄り、
  後ろがぼけ、メモが画面の中央へ）。書きやすいように、カレンダーより少しだけ正面を
  向けて持っています。
- **そのまま打てば書けます。** 日本語も IME（IBus）を通して書けます（変換中の下線と
  候補は紙の上に出ます）。Enter で改行、← → ↑ ↓・Home / End・BackSpace / Delete。
  紙の上をクリックすると、そこにカーソル。
- **めくる**：ホイール、Page Up / Down。紙はカレンダーと同じくリングを越えて後ろへ
  回ります。最後の書いた紙からさらにめくると**新しい白紙**（Ctrl+N でも）。
- **戻す**：Esc、右クリック、メモの外をクリック。棚に戻ると、表の紙は今書いたものに
  なっています。
- 書いたものは最後の変更から 1 秒後と、めくったとき・戻したときに
  `$XDG_DATA_HOME/desk/memo` に残ります（紙と紙の間は改ページ文字 1 行のテキスト
  ファイル。最後の白紙は残しません）。
- 字は手書きの書体で書きます（`fonts-klee` の Klee One があればそれ、無ければ明朝）。

#### 予定と TO DO — 付箋を貼る

**日付をクリックすると、カレンダーが左へ寄り、右から手帳（リングのバインダー）が
滑り込んできます。** その日のページが開いていて、表紙の内側には 6 色の付箋のパッドが
貼ってあります。

- **色を選ぶ**：パッドをクリック（一番上の 1 枚の角がめくれて「これが次に剥がれる」の印）。
  書いている途中の付箋の色も変わります。
- **貼る**：ページの PLANS か TO DO の、鉛筆で枠だけ描いてある場所をクリックすると、
  パッドから 1 枚剥がれて飛んできて貼られ、書けるようになります。何もクリックせずに
  打ち始めても、予定の付箋が 1 枚剥がれます。
- **書く**：日本語も書けます（IBus。変換候補は付箋のすぐ下に紙片で出します。Mozc も
  Wayland のセッションでは候補を IBus に渡すので、同じ紙片です）。
  **Esc でやめる。**
- **時間を決める**：予定を書いている間は、手帳の下に**透明な定規**（0〜24 時の目盛り）が
  出てきます。定規の上で**押したまま横に引くと、その間が蛍光ペンで塗られ**、何時から
  何時までの予定になります（15 分刻み）。クリックだけならその時刻から（長さが決めて
  あれば、そのまま動きます）。ホイールで 15 分ずつ前後。左端の **ALL DAY** で時間なし。
  ポインタの所には鉛筆の線と「14:00」の札が出ます。頭に打っても決まります：
  `10:00 歯医者`、`10:00-11:30 会議`、`10時〜12時 面談`、`9時半から11時まで`、
  全角の `１４：３０` でも。
- **Enter で貼る**：付箋が手帳のページから**下の端からめくれて剥がれ**、弧を描いて
  カレンダーへ飛び、その日の場所（月のページなら日付の升の旗、週なら列、日なら
  その時間の行）の形になりながら、ぺたっと押し付けられます。手帳には鉛筆で
  「10:00–11:30 会議」と 1 行書き留められます（色は左の小さな切れ端で）。
  手帳の日がカレンダーのページにないときは、カレンダーが先にそのページまでめくれます。
- **書き直す**：手帳の鉛筆の行か、**カレンダーに貼ってある付箋そのもの**をクリックすると、
  付箋がカレンダーから剥がれて手帳まで飛んで戻ってきます。書き直して Enter でまた
  カレンダーへ、Esc なら元のまま戻ります。
- **剥がす**：鉛筆の行か、カレンダーの付箋を**右クリック**。付箋がめくれて落ちていき、
  手帳の行は消しゴムで消えます。中身を全部消して Enter でも剥がれます。
- TO DO の行の四角をクリックすると、赤でチェックが入って線で消されます。
- 手帳を開いたまま ← → で前後の日、↑ ↓ で前後の週へ（カレンダーも付いてきます）。
  手帳とカレンダーの外をクリックするか Esc で、手帳は右へ帰っていきます。
- **日のページの時間の行をクリックすると**、その時刻の予定の付箋が出てきます
  （14 の行なら 14:00）。**TO DO の欄をクリックすると**新しい TO DO の付箋。
  今日のページの右上には TODAY の判が押してあります。

貼った付箋はカレンダーに出ます。月のページでは升の中、日付の下に小さな付箋の旗
（予定が先、TO DO は四角つき。時刻と書いたこと。3 枚目からは +n）、週のページでは
各日の列に、日のページでは**始まりから終わりまでの時間の行にまたがって**
（重なる予定は横に並べて）、時刻なしは NOTES、TO DO は TO DO の欄に。年のページでは
日付の下に色の点。棚の上のカレンダーにも色の印が付きます。

付箋は `$XDG_DATA_HOME/desk/calendar`（ふつうは `~/.local/share/desk/calendar`）に
1 行 1 枚で書かれます（日付・予定か TO DO か・色・時刻（`10:00` か `10:00-11:30`）・
済んだか・書いたこと、タブ区切り）。
- ページの外をクリックするか、右クリック、Esc で棚に戻します。次に手に取ると今月から。

`desk-preview --calendar [-s 720x450] [-o file.png]` で、拡大したカレンダーのいろいろな
状態（そのまま、端が立ったところ、めくりの途中を両方向）を 1 枚に並べて書き出せます。

## 素材 — 何年も使われた机

新品の展示家具に見えないために足したものは、形ではありません。**傷とムラと汚れ**、
それと**照明**です。ポリゴンは一枚も増えていません。

### 照明は一灯だけ

部屋を照らしているのは**机の手前右に置かれた一台のスタンド**です。近く、傘があり、
明るさは中央から左奥（Control Panel のある隅）へ 3〜4 倍落ちます。以前は部屋の真上に
大きなソフトボックスがあり、どこも同じ明るさでした。**均一な明るさは「スタジオで撮った
CG」の主成分**です。

距離減衰だけでは足りません。それだけだと全体が同じ方向から同じくらい照らされたまま
なので、**傘の角度**（`ROOM_LAMP_CONE_IN/OUT`）を入れてあります。これが「誰かが
明かりを点けた」に見える部分です。天井の明るさも 0.255 → 0.128 に落としました。
明るい一様な天井が全部の影を埋めていて、スタンドに仕事が残っていませんでした。

計器やメモ帳の**面は cairo が固定の明るさで描いて**焼いた本体に重ねています。暗い側の
カレンダーが明るい側の時計と同じ明るさだと、どちらも「机に貼ったシール」に見えるので、
`room_lamp_at()` でその場所に届く光を測って落としています。

**机の上に重ねて描く物も、同じスタンドで照らします。** 窓の紙・折りたたんだ紙束・
めくれた角・折り目・広がる紙の縁の影と明暗は、以前は「光は画面の上から」という平面の
約束事で描いていて、影が画面の下へ落ちていました。部屋の物の影は奥（画面の上）と左へ
伸びるので、紙だけが別の明かりの下にあるように見えていました。今はスタンドの真下の点を
部屋のカメラで画面に投影し（`desk_light_desk`）、影はそこから離れる向きに、遠いほど
長く落ちます。机の上の場所によって影の向きが扇のように変わり、スタンドの近くでは
ほとんど落ちません。反った角や折り目も、スタンドに向いた面が明るく、反対の面が暗く
なります。本棚・Control Panel・ポストを見ている間は、それぞれ上と前からの明かりです。

### 傷は「幅を持った線」

最初の二つの実装は両方とも失敗しました。**リッジノイズの高い冪**は稜線しか残らず、
幅ゼロの線は見えません。**ノイズ場の等高線**は幅が勾配の逆数になるので、同じ傷が
場所によって 1 画素未満になったり太いボケになったりして、引っかき傷ではなく**水染み**
に見えます。

いまは間隔を決めて線を並べ、低周波ノイズで曲げ、**幅をワールド単位で指定**しています
（`scratch_at`）。傷が傷であるのは細いからです。そのうえでほとんどを消し、残ったものも
長さ方向で出たり消えたりします。**一面に均等に傷が入った面はテクスチャマップ**で、
四か所に入った面が「使われた面」です。

### 傷はどこにでもは付かない

摩耗とノイズの違いは**どこに出るか**です。`room_touch()` は手が実際に行く場所
— 前縁、椅子の正面（中央からは少しずれている）— を返し、`room_sun()` は窓のある
手前左を返します。ニスはその分だけ薄くなり、日に当たった側だけ色が抜けます。

## 必要なもの

いちばん簡単なのは、配布ごとのインストーラです（下の「インストール」）。依存の
パッケージも、おすすめのプログラムも一緒に入れます。自分でビルドするときに要るもの:

- wlroots 0.18（Debian 13 と、Fedora 43 以降の `wlroots0.18` にはあります。Ubuntu 24.04 は
  0.17、Ubuntu 26.04 は 0.19、Arch は 0.20 しか持っていないので、インストーラが 0.18.3 を
  公式のリリースから `/opt/desk-wlroots` にビルドし、DEsk だけがそれを使います）
- wayland、wayland-protocols、xkbcommon、cairo、pixman、fontconfig、libdrm、PAM

- libpulse（任意 — 机の音。無ければ実行時に ALSA を試します。`-Dsound=disabled`）
- libinput（任意 — タッチパッドとマウスの設定。wlroots が libinput に対応していれば）
- EGL, GLES, gbm（任意 — あれば部屋を GPU で焼きます。無ければ C が焼きます）
- Xwayland と xcb（任意 — あれば X11 だけのアプリも開けます。無ければ Wayland のアプリだけ）
- 書体: URW の基本 35 書体（`fonts-urw-base35`: Palatino・Helvetica・Courier に当たる
  P052・Nimbus Sans・Nimbus Mono PS）と Noto CJK（`fonts-noto-cjk`）。手書きの
  メモには `fonts-klee`（任意）。どれも無ければ近いもので描きます（下の「書体」）

### グラフィックの段階（Graphics）

Shell Settings の DESK のページの **Graphics**（`shell.conf` の `graphics`）で、机が
どれだけ描くかを 5 段階から選べます。**インストールのとき、機械を軽く調べて段階を選び
ます**（`desk-index --suggest`：グラフィック（無ければ CPU）を 2 秒ほど走らせ、スレッドの
数とメモリと合わせて、最初の部屋がおよそ 1 分以内に焼ける一番上の段階。Ultra は GPU・
8 スレッド・12 GB 以上のときだけ、GPU が無ければ Low まで。メモリ 2 GB 未満は 2D。
さらに**紙を折る 1 コマを CPU で描く時間**を測り、そのコマが 5 ms に収まる段階まで
（動いている紙の手間は High を 1 として Medium 0.56、Low 0.25）。GPU が速くても CPU が
遅い機械は、グラフィックだけで決めると High になり、紙を折るたびに 30 fps に落ちて
いました。i3-6100U の速さに絞ると Medium、2010 年ごろの機械なら Low になります）。選んだ
段階は機械全体の既定として `/etc/xdg/desk/shell.conf` に書き、各ユーザーが Shell Settings で
変えた値（`~/.config/desk/shell.conf`）がそれより優先します。`sudo DESK_GRAPHICS=low
sh scripts/install_debian.sh` のように指定すれば、調べずにその段階にします。調べられない
ときの既定は **High**（今までどおりの机）です。
切り替えるとその場で効き、部屋はその段階で焼き直します（焼き上がるまでは前の部屋の
まま使えます。段階ごとにキャッシュが残るので、戻すときは数秒）。

| 段階 | `graphics` | 部屋の焼き方 | 机の上 |
| --- | --- | --- | --- |
| Ultra | `ultra` | 1 画素 9 サンプル（1600 幅まで）、向き直りのフィルムは半分の大きさ。GPU で焼ける機械では、大きい画面で 2560 幅まで | High のすべてに加えて、**動いている間も細かさを落としません**：丸めて捨てる紙は等倍で毎フレーム（大きな紙で 1 コマが重い機械では毎秒 30 回）、玄関の雨や雪は毎フレーム、大きさを変えている間の影は毎回描き直し、Control Panel の真空管は毎秒 30 回 |
| High | `high` | 今までどおり（1440 幅、GPU で焼ける機械は 1920 まで。1 画素 4 サンプル、フィルムは 4 分の 1） | 影・ぼかし・フェード・アニメーションすべて |
| Medium | `medium` | 1280 幅まで | 動いている紙（折る・最大化・大きさを変える・丸めて捨てる）は 4 分の 3 の細かさで描いて引き伸ばす。字・数字・ボタン・計器の針は画面の細かさで描く（部屋は 1280 相当のまま）、Control Panel の計器は毎秒 8 回、丸める紙の面は 70 px ごと |
| Low | `low` | 960 幅まで、フィルムは 6 分の 1 | カレンダー・メモを手に取るときの本棚のぼかし無し。施錠は歩いて行かずに玄関のドアがすぐ降りる。玄関の雨や雪は毎秒 15 回、Control Panel の計器は毎秒 6 回。動いている紙は半分の細かさで描いて引き伸ばす。字・数字・ボタン・計器の針は画面の細かさで描く（部屋と玄関、雨や雪は 960 相当のまま）、ネットワークの針は粗めに、丸める紙の面は 84 px ごと。画面の合成が CPU（pixman）の機械では、眺めへの動きは 2 コマを重ねず 1 コマずつ。ログインの明かりは 0.5 秒 |
| **2D Fallback** | `2d` | **640 幅で一度だけ**、1 画素 1 サンプル（軽くぼかす）、フィルム無し（向き直りは切り替え）、光のにじみ無し | **影・ぼかし・透過のフェード・すべてのアニメーション・動きながらのレイトレースを切ります**。窓の開閉・折りたたみ・引き出し・本棚・ページも一瞬で。ログインの明かりもすぐにつきます。施錠はドアがすぐ降り、玄関は半分の大きさで一度だけ焼き、雨や雪は動きません。Control Panel の計器は毎秒 2 回。時計は時と分だけ（秒の数字を描かず、コロンも電池も点滅しない）なので、何もしていない机は何も描き直しません。部屋は 640 相当でも、字・数字・ボタンは画面の細かさで描きます。記念日の演出は時計と音だけ |

Ultra でも、眺めへ向き直る間のフィルムは**部屋の半分の大きさ**のままです。フィルムは
18 コマを先に焼いておくパラパラ漫画で、等倍にすると焼く手間が 4 倍、置いておくメモリも
1 本 150 MB ほど（1920x1080 で。半分の大きさなら 37 MB）になります。動きの終わりの
1 割で、等倍の眺めがフィルムの上にフェードインします。

2D フォールバックは、GPU の無い機械や仮想マシン（llvmpipe などで CPU が描く）向けの
いちばん軽い段階です。GPU なし・2 コアで、最初のログインの部屋の焼き上げが 581 秒から
16 秒に、そのあとの 1 フレームも平均 2 ms から 0.5 ms になります（上の表）。部屋は
1 画素 1 サンプルで焼いて軽くぼかします（4 サンプルの 4 分の 1 の手間で、画面に引き伸ばすと
見た目はほとんど同じ。以前の 4 サンプルでは 67 秒でした）。2D は別に作った机ではなく、
同じ机の効果を切ったものです（Windows の Aero を切ったときのように）。Shell Settings
自身も 2D ではメモ帳を引き出さず、ページもめくらずに切り替えます。

**CPU で動いているとき**（画面を GPU ではなくプロセッサが描いているとき：GPU の無い機械、
3D を有効にしていない仮想マシン、ドライバの入っていない GPU）は、**2D フォールバックで
動きます**。見分けるのは画面の合成で、pixman か、GL が llvmpipe などの CPU で動く
ラスタライザのときです（VMware の 3D ドライバのように名前に「LLVM」とだけあるものは GPU
です）。Shell Settings で自分で Graphics を選んでいれば（自分の `shell.conf` に
`graphics` があれば）そちらに従います。インストーラが機械に選んだ段階は GPU を前提にした
見込みなので、CPU のときは 2D が勝ちます。そのことは次のように知らせます。

- **郵便受けに手紙**「CPU で動いています ― 現在 CPU で動いています。ドライバー等を
  確認してみてください。仮想環境の場合は設定（3D アクセラレーション）を確認してみて
  ください」。ログインして机が整ったときに届きます。毎回ではなく、一度届いたら 1 週間は
  届かず、描いているもの（pixman・llvmpipe など）が変わればまた届きます
  （`~/.local/state/desk/cpu-letter`）。角の裏の「シェルの設定」で Shell Settings が開きます。
- **Shell Settings の Graphics** に赤い字で同じことと、何が描いているか（`(llvmpipe …)`）。
  そのとき Graphics は 2D フォールバックが選ばれた状態で出ます。
- ログに `the screen is drawn on the CPU (…): the desk draws in 2D Fallback`。
  `DESK_ON_CPU=1`（または `0`）で、見分けずにそうだと決められます。

この機械がどのくらいかは **DEsk Experience Index**（`desk-index`、下の節）で
確かめられます。各部分が 3 以上なら日常の操作に足ります。GPU が無いと 3D の点が
2.9 までに抑えられますが、変わるのは最初の部屋の焼き上げの長さだけです。

## デスクトップ環境として

DEsk は机を描きます。机の上でする仕事のほうは、**すでにある自由なソフト**でします。
ウィンドウマネージャ（窓を並べるだけ）とデスクトップ環境（周りのソフトまで揃って
いる）の間を、自作を増やさずに埋めるのが方針です。DEsk と一緒に入れるソフトを
決めて、セッションがそれらを動かし、設定の画面からそれらを呼びます。

### どこまでを DEsk が作り、どこからを借りるか

| | DEsk が作る | 両方（物は DEsk、仕事は借りる） | 借りる |
| --- | --- | --- | --- |
| 何を | 部屋として描かれ、物として扱うもの。コンポジタにしかできないこと | DEsk が物を描き、仕事はほかのプログラムやサービスがする | プログラムと、システムの設定の画面・常駐するもの |
| 例 | 紙の窓とその枠、引き出し、本棚（ALL APPS）、時計、Control Panel、ポスト、玄関の扉、カレンダーとメモ。キーボードとポインタとそのキー（音量・メディアキーを含む）、画面とその電源、離席、ロック、画面の配置を覚えること。Shell Settings（DEsk 自身の設定） | 音量のつまみとミュート（PipeWire / PulseAudio）、明るさ（logind）、Wi-Fi・Bluetooth のレバー、ポスト（DEsk が通知デーモン）、トレイの紙片（アプレット自身の項目）、時計の MEDIA（MPRIS）、スクリーンショット（grim）、日本語入力（IBus への橋渡し） | ネットワークの接続、Bluetooth の機器、音の機器とアプリごとの音量、画面の配置と解像度、プリンタ、ほかのアプリの見た目、既定のプログラム、ディスク、認証エージェント、キーリング、ポータル。そしてアプリそのもの |

新しいことを決めるときの決まり：**部屋の物として描かれるものか、コンポジタの内側で
しかできないことだけを作ります。** それ以外はまず、Wayland（wlroots）でそのまま動く
既存のプログラムを探して借ります。借りられるものが無いときも、まず別の既存の
プログラムを探し、自作は最後です。KDE の System Settings や kcmshell は Plasma の外では
動かないので使いません。Xfce と MATE の設定ダイアログのうち、X11 でしか動かないもの
（キーボード・マウス・MATE の外観）や、Xfce の設定デーモン（xfsettingsd）がないと
効かないもの（画面・外観）も使いません。

借りる側の仕事は、Shell Settings の System タブの行と、Control Panel の右クリックから
開きます（下の「Shell Settings」）。入っていないプログラムの行は薄く印刷され、その
配布での名前で「入っていません — 例：nm-connection-editor」と書いてあります。

まだ誰も受け持っていない仕事と、それを埋める候補（DEsk が作るか、借りるか）は
`docs/design.md` の「線引き」にまとめてあります。主なもの：夜間の色温度
（wlr-gamma-control を足せば wlsunset・gammastep を借りられる）、サスペンドのボタン
（logind）、範囲のスクリーンショット、二つ目の画面の部屋（いまは机の続きの板だけ。
下の「画面が二つ以上のとき」）。

### 一式を入れる

```sh
sudo sh scripts/install_debian.sh     # DEsk と一式（install_ubuntu.sh、install_arch.sh、install_fedora.sh も同じ）
sh scripts/install-desktop.sh         # プログラムだけ（入れるものを見せて、聞いてから sudo）
sh scripts/install-desktop.sh --extras   # オフィス・メールなども
sh scripts/install-desktop.sh --dry-run  # 見せるだけ
```

`install-desktop.sh` は apt（Debian・Ubuntu）・dnf（Fedora）・pacman（Arch）・
zypper（openSUSE）で動きます。それぞれの物に配布ごとの名前を並べてあり、パッケージ
マネージャが知っている最初の名前を入れます。Debian・Ubuntu ではパッケージ一つにも
できます（equivs）:

```sh
equivs-build packaging/debian/desk-desktop.equivs
sudo apt install ./desk-desktop_*_all.deb
```

Xfce と MATE の昔ながらの GTK のソフトが中心なのは、メニューバー・素直な道具・文書と
いう、紙に合う形の窓だからです。軽く、すぐ起動し、Wayland でそのまま動き、既定アプリ
の表（`desk-mimeapps.list`）に従います。GTK 3 のソフトは KDE の server-decoration で
枠を DEsk に頼むので、GTK のタイトルバー無しで紙に載り、明朝の見出しが付きます
（下の「ウィンドウの枠」）。KDE のソフトはその次、ヘッダーバーで自分の枠を描く GNOME
のソフトは最後です。

**セッションがすること**（`desk-session` から起動したとき、つまりログイン画面や
コンソールから DEsk をデスクトップとして始めたときだけ。窓の中や入れ子では
しません）:

- **D-Bus と systemd に画面の場所を知らせる**（`dbus-update-activation-environment
  --systemd`）。ポータル（ファイルの選択・画面共有）やキーリングなど、D-Bus から
  起こされるものが DEsk の画面を見つけられるように。
- **自動起動**（freedesktop.org の XDG Autostart）：`~/.config/autostart` と
  `/etc/xdg/autostart` の .desktop を、仕様どおり（`Hidden`、`OnlyShowIn`・
  `NotShowIn`、`TryExec`、`X-GNOME-Autostart-enabled`、同じ名前はユーザーの方が
  勝つ）に起こします。止めたいものは、同じ名前で `Hidden=true` のファイルを
  `~/.config/autostart` に置きます。どのデスクトップとも書いていないのに机とぶつかる
  もの（別の通知デーモン、X のスクリーンロッカー・スクリーンセーバー、他の
  デスクトップの認証エージェントなど）は起こしません。
- **DEsk 自身の自動起動**（`OnlyShowIn=DEsk`、`desk-session-helper` が入って
  いるものを選んで起こす）：認証エージェント（MATE → Xfce（xfce-polkit）→ LXDE
  （lxpolkit）→ GNOME → KDE → LXQt の順）、キーリング、入力メソッド（IBus か
  fcitx5）、ネットワークアプレット（トレイに出る `nm-applet --indicator`）、取り外せる
  ディスク（udiskie：挿したら開いて手紙、開いている間トレイに紙片）、電池
  （poweralertd、Arch は batsignal：残り少なくなったら手紙）。Bluetooth は Blueman
  自身の、ソフトの更新の知らせ（package-update-indicator、Debian・Ubuntu）はそれ自身の
  自動起動で。
- **カーソル**：nwg-look や GNOME Tweaks が GSettings に書いたカーソルのテーマと大きさを
  `XCURSOR_THEME`・`XCURSOR_SIZE` に写し、DEsk 自身のポインタと X のアプリもそれに
  従います（次のログインから）。
- 環境変数：Qt の GTK プラットフォームテーマがあれば `QT_QPA_PLATFORMTHEME=gtk3`
  （Qt のソフトが周りの GTK のソフトと同じ色・アイコン・書体・ファイル選択になる。
  Xfce や MATE の中で Qt が自分で選ぶのと同じ）、無くて KDE の Plasma 連携があれば
  `kde`、自分で決めてあればそのまま。GTK のテーマには触りません（Wayland の GTK は
  `org.gnome.desktop.interface` を読みます。変えるのは Shell Settings の「ほかの
  プログラムの外観」から）。入力メソッドは下の「日本語入力」。
- **PATH と XDG_DATA_DIRS**：`desk-session` は自分のフォルダを PATH に足すので、
  `/opt/desk` などに入れても動きます。その share が DEsk の既定アプリの表を持って
  いれば XDG_DATA_DIRS の先頭に。snap と Flatpak のアプリのメニュー項目のフォルダ
  （`/var/lib/snapd/desktop`、`/var/lib/flatpak/exports/share`、
  `~/.local/share/flatpak/exports/share`）も足します（ログイン画面はふつう
  `/etc/profile.d` を読まないので、足さないと本棚と既定のブラウザに出ません）。

**日本語入力（IME）**:

- キーボードの配列は**システムの設定**（`/etc/default/keyboard`、無ければ
  `/etc/X11/xorg.conf.d/00-keyboard.conf`、環境変数 `XKB_DEFAULT_*` があればそれ）に
  従います。以前は何も見ずに US 配列で、日本語キーボードの**半角/全角・変換・無変換・
  カタカナひらがな**が効かず、IME を切り替えられませんでした。
- 入力メソッドは**要るときだけ**起こします：日本語・中国語・韓国語・ベトナム語・タイ語の
  ロケールか、IBus にキーボード以外のエンジン（Mozc など）が設定されているとき
  （`desk-session-helper ime-kind`）。英語などでは何も起こさず、何も出ません。
- 入力メソッドは**トレイ**に出ます（時計からは外しました）。IBus はパネル自身の
  トレイ項目（StatusNotifierItem）を出させて使います。紙片には今の入力方式（Mozc なら
  「あ」／「A」、半角/全角に合わせて変わる）、メニューには入力モード（直接入力・
  ひらがな・カタカナ…）、ツール、エンジンの一覧、設定、絵文字の選択。fcitx5 は
  fcitx5 自身のトレイ項目です。
- IBus の場合、Wayland のアプリ（GTK・Qt6）は **DEsk を通して入力メソッドを使います**
  （text-input）。キーはまず IBus へ行き、IBus が使わなかったキーだけが、修飾キーの
  状態と順番を保ったまま窓に届きます。DEsk は窓の位置を知っているので、**Mozc の
  変換候補は文字カーソルのすぐ下に出ます**（アプリが IBus に直接つなぐと、Wayland
  では窓の位置が伝わらず画面の左上の隅に出ていました）。
- そのため IBus のときは `GTK_IM_MODULE`・`QT_IM_MODULE` を設定せず（他から引き継いで
  いても外し、systemd のユーザー環境からも外します）、Qt6 には
  `QT_IM_MODULES="wayland;ibus"` を渡します。X のアプリ（Xwayland）は XIM
  （`XMODIFIERS=@im=ibus`）。fcitx5 の場合は今まで通り直接つなぎます。
- 変換候補の窓（IBus のパネルが出すもの。Mozc も Wayland のセッションでは自分の窓を
  使わずこれを使います）は、**紙の窓ではなく、そのときだけ出る小さな窓**です。書いて
  いる文字のすぐ下に、枠も影も付けずに出て、キーは取らず、消えるときも何も起きません。
  候補をクリックしても、キーは書いている窓に残ります。IBus は X があれば X で動かす
  ので（`GDK_BACKEND=x11,wayland`）、候補の窓は IBus 自身が文字カーソルの下に置きます。
  Wayland のアプリ（DEsk が IBus に場所を伝えます）でも X のアプリ（XIM が伝えます）でも
  同じです。X が無ければ Wayland の窓になり、DEsk が文字カーソルの下に置きます。以前は
  Wayland の窓として紙に載せてキーまで取り上げ、候補が消えるたびに丸めて放り投げて
  いました。

**机とのつながり**:

- **Print** で画面全体、**Alt+Print** で前の窓（紙ごと）のスクリーンショット
  （grim）。`ピクチャ/Screenshots` に入り、クリップボードにも乗り、ポストに手紙が
  届きます（`desk-screenshot`）。
- **Control Panel** のネットワークのメーターをクリックするとネットワークの接続
  （nm-connection-editor）。WIRELESS・BLUETOOTH・VOLUME を**右クリック**すると、
  それぞれネットワーク・Bluetooth の機器（blueman-manager）・音の機器
  （pavucontrol → pavucontrol-qt → MATE の音量の設定）。Shell Settings の System タブの行と
  同じプログラムを同じ順に使います。机へ向き直って、窓は机に出ます。
- キーボードの**音量・ミュート・再生のキー**（XF86AudioRaiseVolume・LowerVolume・Mute・
  Play・Pause・Next・Prev）は DEsk が受けます（Wayland ではコンポジタにしか見え
  ないので）。音量は時計とつまみと同じミキサー、再生は時計の MEDIA と同じプレーヤー。
  ミュート中に音量を上げるとミュートが外れます（下げてもミュートのまま）。
- アプリが自分の窓を前に出すこと（xdg-activation：メールのリンクからブラウザ、
  二度目の起動で前の窓など）、動画の拡大縮小（viewporter）、フレームの時刻
  （presentation-time）に応えます。
- 画面の配置（wlr-output-management）：wdisplays・wlr-randr・kanshi で、画面ごとの
  モード・位置・向き・オン/オフを変えられます。ツールが言ったスケールは机の「ものの
  大きさ」で、shell.conf の `scale` に書かれます（プログラムの窓は拡大しません）。
  DEsk は、つながっている画面の組ごとに、ツールが決めた配置を
  `~/.config/desk/displays.conf` に覚え、同じ組がそろうと（起動時・抜き差し）
  そのとおりに戻します。机が描かれるのは位置 (0,0) の画面です（ほかの画面は下の
  「画面が二つ以上のとき」）。ツールで消した画面は、ツールでまた点けられます。
  そのときツールがほかの画面と重なる位置（多くは 0,0）を言ってきたら、点いている
  画面の右隣に置きます（消した画面の位置はツールに伝わらないため）。モードを
  言わなければ、消す前のモードで点けます。
- 離席（ext-idle-notify・idle-inhibit・wlr-output-power-management）：swayidle や
  wlopm も使えます。動画を再生しているプレーヤーやブラウザ（Wayland のもの）は、窓が
  見えている間、画面を点けたままにできます。X11 のアプリ（Spotify・VLC など）と
  Flatpak のアプリ（ポータル経由）が頼む org.freedesktop.ScreenSaver の Inhibit も
  受けます（DEsk がその名前を取ります。ほかのスクリーンセーバーが持っていればそちら）。
- 画面共有：xdg-desktop-portal-wlr は、どの画面を共有するかを slurp などで聞きます
  が、それにはレイヤーシェルが要るので、DEsk では `desk-screen-chooser` が普通の窓
  （zenity。無ければ kdialog・yad）で聞きます。画面が一つなら聞かずにそれを共有
  （`/etc/xdg/xdg-desktop-portal-wlr/DEsk`）。共有できるのは画面全体で、窓ごとはまだ
  （wlroots 0.18 にその仕組みが無いため）。
- まだ無いもの：外のロッカーのための ext-session-lock（DEsk には自前の画面ロックが
  あります）、レイヤーシェル（slurp での範囲選択など）、wlr-gamma-control（夜間の色
  温度）。

## 画面ロック — 玄関の前

**Super+L** か Control Panel の **LOCK** ボタン（またはログインセッションで
`loginctl lock-session`、マシンがスリープに入るとき）で画面をロックすると、机は
**玄関のドアの向こう**になります。玄関は**その時刻と天気のまま**です（下の「時刻と天気」）。

**閉めるときは、開けるときの逆**です。机からなら本棚へ向き直り、本棚の前から
**後ろ向きに戸口を出て**、ドアが内側から閉まり、鍵の前に屈んで**鍵を回して閉め**、
一歩下がります（約 3.5 秒。本棚・Control Panel を見ていたときはそこから出ます）。歩くときの頭の上下は
Shell Settings の「Camera bounce」（カメラの揺れ）で低く、または無しにできます。
ポスト・引き出しを開けているとき、スリープの前（logind）は、ドアがすぐに下ります
（スリープ前以外は少し離れたところから歩いて来ます）。

ドアの前では、見える
のはほぼドアだけです：胡桃材のドア、すりガラスに透ける部屋の明かり、両脇の煉瓦と
白い枠、右の壁のランタン、頭上の玄関灯。どれも 3D で光と影が付いています。

- ドアには**看板**が釘から紐で**掛けて**あります。自分の**ピクチャ**（`~/.face`。
  SVG なら PNG にして使います。無ければ AccountsService のもの、それも無ければ名前
  の頭文字）と**名前**（パスワードファイルの本名、無ければログイン名）が描いて
  あります。
- その下の真鍮のプレートが**パスワードの入力欄**、その**すぐ横に鍵**が鍵穴に挿さって
  います。打つと入力欄に一文字ごとに琥珀の灯りが点き、後ろにキャレットが光ります。
  BackSpace で一つ消し、Esc と Ctrl+U で全部消し、**Enter（または鍵をクリック）**で
  確かめます。
- 確かめるときは、**鍵の前に屈み込んで鍵を回してみます**（入力欄には光が走ります）。
  違えば**鍵は回らず**、がちゃっと戻り、入力欄が赤く「パスワードが違います」と出て、
  元の位置へ下がります。Caps Lock が入っていればプレートの下に出ます。
- 合えば、**鍵が 90° 回ってがちゃりと開き**、一歩下がると**ドアが内側へ開いて**、
  戸口の向こうに部屋（本棚の前）が見えます。そのまま**戸口を通って中へ**歩き、
  本棚の前に立ったところから、**本棚から机へ向き直るいつものカメラの動きで机に
  座ります**。
- 本棚を見ていたときは本棚、Control Panel を見ていたときは Control Panel の前へ
  入って戻ります。ポスト・引き出しを開けていたときは、ドアが消えてその場面に戻ります。
- 戸口の奥の**部屋も 3D で組んであります**。机・脚・本棚・ポスト・壁・床を部屋の
  寸法どおりに置き、本棚の前からの眺めと机の真上からの眺めを、撮ったカメラから
  投げ返して貼ります。戸口を抜けると部屋の中を歩いて本棚の前に着き、最後のコマが
  そのまま本棚の眺めになります。
- 絵は**この場面だけの小さなレイトレーサー**で描きます（メートル単位の 3D、玄関灯・
  ランタン・月と太陽の光、空の明かり、柔らかい影、真鍮の照り返し、フィルム調のトーン、光のにじみ）。
  カメラが動いている間は、ゲームのようにフレームレートに合わせて解像度を落として
  毎フレーム描き直し、止まったところで細かく描き直します（別のスレッドで。机は
  止まりません）。
- パスワードはログインと同じく **PAM** で確かめます（サービス `desk` =
  `/etc/pam.d/desk`、中身は `login` を include。無ければ `login`）。別のスレッドで
  確かめるので、間違えたときの数秒の待ちで机は止まりません。打ったものは確かめに
  渡した時点で消します。
- ロック中は、窓にもショートカットにもキーとポインタが届きません（VT の切り替え
  Ctrl+Alt+F1… とノートの明るさキーだけは効きます。ポインタで押せるのは鍵だけ）。
  黒い覆いが全部の出力を覆い、その上にドアが出ます。logind にはロック中であること
  を知らせ（LockedHint）、`loginctl unlock-session` ならパスワード無しで開きます。

### 時刻と天気

玄関は、いまの**時刻**と**天気**で変わります。

- **時刻**：太陽の高さと方角を、タイムゾーンの都市（`/usr/share/zoneinfo/zone1970.tab`。
  例：Asia/Tokyo なら東京）の緯度経度から計算します（ドアは南向き）。朝は横から日が
  差し、夕方は低い暖かい光、昼は庇が高い日差しを遮り、夜は玄関灯とランタン、月の
  明かり（満ち欠けで明るさが変わります）。玄関灯とランタンは**明暗センサー付き**で、
  夕方に点き、朝に消えます（曇りや雨の日は長く点いています）。
- **天気**：晴れ・薄曇り・曇り・霧・雨（霧雨〜大雨）・雪・雷雨。雨の日は**壁が濡れて
  色が濃くなり**、踏み石に水たまりができ、**雨の筋**が玄関灯に光ります。雪の日は
  上向きの面（ランタンの屋根、看板の上、煉瓦の段、リースの上）に**雪が積もり**、
  **雪が舞います**。霧は霞がかかり、雷雨は時々**稲光**が走ります。
- 天気はタイムゾーンの都市の位置だけを **open-meteo.com** に 30 分ごとに問い合わせます
  （`curl`、無ければ `wget`。送るのはその緯度経度だけです）。Shell Settings の
  「The real weather at the front door」を切にすると問い合わせず、いつも晴れです。
- 動くもの（雨・雪・稲光・電飾のまたたき・風船のひも）はドアとは別の薄い紙に重ねて
  描くので、ドアをトレースし直すことはありません（ロック中、1440×900 で CPU 1 コアの
  1 割弱）。太陽が動くと数分おきに、止まったまま静かに細かく描き直します。

### 決まった日には

ある決まった日には、玄関と時計にちょっとした仕掛けがあります。何が起きるかは、その日の
お楽しみです。設定のスイッチはありません（誕生日は Shell Settings の「Your birthday」に
年月日を入れておくと、その日に）。始まった演出は Esc で止まり、音は「Sounds」の設定に
従います。

## 画面の消灯

キーにもポインタにもタッチにも触らずに `screen_off`（Shell Settings の SCREEN、既定
10 分）たつと、画面を消します。`lock_on_screen_off`（既定 yes）なら、その前に玄関の
ドアを閉めます（歩く演出は無し）。何かに触れると点き、そのとき押したキーやクリック、
それから 0.8 秒の間のクリックとキーは窓に届きません（モニターが点く前のクリックが窓に
当たらないように。ポインタの動きはそのまま）。ロック中は 1 分で消えます。

- 実機（DRM）では出力そのものを切り、点けるときに元のモードに戻します。入れ子では
  窓を黒で覆い、描くのをやめます
- 眠ると「抜かれた」と知らせるモニター（HDMI や DisplayPort の、眠るとホットプラグの
  線を落とすもの）でも、セッションは終わらず、画面が戻るのを待ちます。暗い間に戻って
  きた画面は暗いまま待ち、キーかポインタで点きます。画面が一つも無い間のキーとクリック
  はどこにも届きません。モニターが眠ったまま戻らないときは、モニターの電源ボタンを
  押してください（モニターのディープスリープなどの省電力の設定を切るか、
  `screen_off = never` でも避けられます）
- 動画のプレーヤーやブラウザ（Wayland の idle-inhibit）は、窓が見えている間だけ
  画面を点けたままにできます（畳まれた・引き出しの中・ロック中は数えません）
- X11 のアプリや Flatpak のアプリは、セッションバスの org.freedesktop.ScreenSaver で
  頼みます。こちらは窓では見分けられないので、頼んでいる間ずっと点けたまま（ロック中は
  数えません）。頼んだアプリが解かずに終わっても、バスから去った時点で解けます
- ext-idle-notify も同じ操作で知らせるので、swayidle も使えます。
  wlr-output-power-management で wlopm も
- 試すとき：`DESK_IDLE_TEST_S=8` で分の代わりに秒

## インストール（Wayland セッション）

Linux でシステムに入れて、GDM / SDDM / LightDM のログイン画面から選びます。
手に入れたフォルダで、使っているシステムのインストーラを実行します（上の「インストール」）。
四つとも同じオプションです:

```sh
sudo sh scripts/install_debian.sh            # install_ubuntu.sh、install_arch.sh、install_fedora.sh も同じ
sudo sh scripts/install_debian.sh --yes      # 聞かずに、すすめる答えで
sudo sh scripts/install_debian.sh --no-apps  # DEsk と要るもの、Shell Settings が開くプログラムだけ
sudo sh scripts/install_debian.sh --bare     # DEsk と要るものだけ（プログラムは何も入れない。コンテナ用）
sudo sh scripts/install_debian.sh --prefix /opt/desk   # 入れる場所（既定は /usr/local）
```

`sh scripts/install_session.sh` は `/etc/os-release` を見て、次のどれかに自分で渡し
（同じオプション）、言ったことを `~/.local/state/desk/install.log` にも残します。
Linux Mint・Pop!_OS は Ubuntu、EndeavourOS・Manjaro は Arch、Nobara などは Fedora として扱います。

| 配布 | スクリプト | wlroots 0.18 |
| --- | --- | --- |
| Debian 13 | `scripts/install_debian.sh` | 配布のもの（`libwlroots-0.18-dev`） |
| Ubuntu 24.04 / 26.04 LTS | `scripts/install_ubuntu.sh` | 配布に無い（24.04 は 0.17、26.04 は 0.19）ので、0.18.3 を公式のリリースから `/opt/desk-wlroots` にビルド（24.04 では Wayland 1.23.1 も）。DEsk だけが RUNPATH で使い、ほかのプログラムには見えません。universe が切られていれば聞いてから入れます。Firefox は snap（snapd が動いていれば `snap install firefox`） |
| Arch Linux | `scripts/install_arch.sh` | 公式のリポジトリには 0.20 しか無いので、入っている `wlroots0.18`（AUR）を使い、無ければ 0.18.3 を `/opt/desk-wlroots` にビルド。Klee One と ibus-mozc は AUR にしか無いので、そう言って代わりのものを使います。ログイン画面が無ければ、コンソールから `desk-session` か LightDM の入れ方を案内します |
| Fedora 43 / 44 | `scripts/install_fedora.sh` | 配布の `wlroots0.18`（`wlroots0.18-devel`）。無い Fedora では 0.18.3 を `/opt/desk-wlroots` にビルド。dnf で入れ、弱い依存（おすすめ）は入れません（GNOME Tweaks が GNOME Shell と GDM まで連れてくるので）。Klee One・Mugshot・電池と更新の知らせは Fedora に無いので、そう言って入れずに済ませます。ログイン画面が無ければ、コンソールから `desk-session` か LightDM の入れ方を案内します |

どのスクリプトも同じ順にします：足りないパッケージを入れる（パッケージの一覧は
スクリプトの頭の表。Shell Settings の **System タブの各行が開くプログラム**と、それが
動くのに要るもの（認証エージェント、キーリング、印刷、IBus）は、`--no-apps` でも必ず
入れます。`--bare` のときだけ入れません）、`build-install` にリリースでビルドして入れる、PAM の
`/etc/pam.d/desk`、ログイン画面の項目 `/usr/share/wayland-sessions/desk.desktop`
（`Exec` は入れた場所のフルパス）、それから**旧名 DeskWM の残り**（`deskwm*` の
コマンド・データ、`/usr/share/wayland-sessions/deskwm.desktop`、`/etc/pam.d/deskwm`）を
見せて、聞いてから消します。そのあと `desk-index --suggest` で機械を軽く調べて Graphics
の段階を選び（上の「グラフィックの段階」）、最後に `desk-settings --check` で、System タブの各行が
何を開くか（無ければ `MISSING` と、それを入れるパッケージの名前）を一覧にします。何度
走らせても同じ結果で、2 回目からは数秒です。

**更新**は、新しいフォルダを手に入れて同じインストーラを
もう一度走らせるだけです（入っていれば「this updates it」と出ます）。入っているものは入れ替わり、
前回のビルド（`build-install`）は作り直して使います。作り直せないとき（別の版の
Meson のもの、以前 sudo で走らせて一部が root のもの）は、消して作り直します。
設定（`~/.config/desk`）と焼いた部屋はそのまま残り、部屋は見た目が変わった更新の
ときだけ焼き直します。途中で止まったときは、端末に出た最後の数行を見るか送ってください
（`install_session.sh` から走らせたときは、全部が `~/.local/state/desk/install.log`
（最後の 1 回分）にも残ります）。

配るためのフォルダには `SHA256SUMS`（全ファイルの SHA-256）が入っていて、
インストーラは**ビルドの前に全ファイルを照合**します。運ぶ途中で壊れたコピー
（USB メモリを取り外し前に抜いた、など）は、どのファイルが違うかを言って止まります。
新しく取り直したコピーまで壊れているときは、その機械のメモリかディスクを疑ってください
（メモリは memtest86+ で調べられます）。git で取ったものには無いので照合しません。

**困ったときのログ**：ログイン画面から入った DEsk は、自分の言ったことを全部
`~/.local/state/desk/session.log` に書きます（一つ前のセッションの分は
`session.log.old`。DEsk から開いたプログラムの出力も入ります）。起動が遅いときは `desk: room:` で始まる行を見てください。
部屋をどの GPU で焼いたか（`tracing on …`）、机・眺めの絵・フィルムがそれぞれ何秒
かかったか、GPU と C の検算が合わなかった層があればそれも出ます。GPU が試運転に
落ちて CPU で焼いているときは `failed its trial: <理由>` の行が出ます。端末から
`desk-window` などで動かしたときは、今までどおり端末に出ます（`DESK_LOG=-` で
ログインのときも書かずにおけます）。

日本語のロケール（`LANG` などが `ja` で始まる）のときだけ、日本語の変換（Mozc）を
すすめるプログラムとして入れます（`--no-apps` では入れません）。IBus 自体はどの言語でも
入れますが、動かすのは日本語・中国語・韓国語・ベトナム語・タイ語のロケールか、IBus に
入力方式を設定してあるときだけです。
設定とデータ（`~/.config/deskwm` など）は、新しい DEsk が最初に起きたときに
`~/.config/desk` などへ移します。

入るもの（prefix が `/usr/local` のとき）:

- `/usr/local/bin/desk` — コンポジタ、`desk-session` — セッションラッパー、
  `desk-settings`（Shell Settings）、`desk-index`（Experience Index）、`desk-preview`、
  `desk-ctl`（困ったときの立て直し・ログアウト）
- `/usr/local/share/icons/DEsk`・`/usr/local/share/themes/DEsk` — アイコンと GTK テーマ、
  `/usr/local/share/desk/desk-dconf-profile` — DEsk のセッションの設定の層
- `/etc/xdg/desk/shell.conf` — インストーラが選んだ Graphics の段階（機械全体の既定）
- `/usr/share/wayland-sessions/desk.desktop` — ログイン項目
- `/usr/local/share/xdg-desktop-portal/desk-portals.conf`、
  `/etc/xdg/xdg-desktop-portal-wlr/DEsk` — ポータルの割り当て
- `/etc/pam.d/desk` — 画面ロックの PAM

依存がもう入っている機械（ほかの配布など）では、ビルドして入れるだけの
`scripts/install.sh`（同じ既定・同じログイン項目の扱い）と、プログラムを入れる
`scripts/install-desktop.sh` を使います。

**消すとき**は、DEsk からログアウトして、ほかのデスクトップ（か文字のコンソール）で、
入れたときのフォルダから `sudo sh scripts/uninstall.sh`。消すもの（DEsk のプログラムと
ファイル、ログイン画面の「DEsk」、機械全体の設定 `/etc/xdg/desk`、インストーラが
ビルドした wlroots の `/opt/desk-wlroots`。`--keep-wlroots` で残す）を見せてから
聞きます。ディストリから入れたパッケージはほかのプログラムも使うので残し、あなたの
もの（`~/.config/desk`・`~/.local/share/desk`・`~/.local/state/desk`・`~/.cache/desk`）
にも触りません。`sudo ninja -C build-install uninstall` だけでは、ログイン項目・
`/etc/xdg/desk`・アイコンのキャッシュ・wlroots が残ります。

ログイン画面に **DEsk** が出ます。TTY から直接始めるなら:

```sh
desk-session
```

入れ子（既存の Wayland / X11 セッションの中）:

```sh
DESK_NESTED=1 desk-session -s foot
# または
./build/desk -s foot
# ウィンドウとして開く（大きさは DESK_SIZE=1600x900 のように変えられます）
./scripts/desk-window
```

入れ子で動かすときの Wayland ソケットは `wayland-0` ではなく **`desk-0`**（空いている
番号）です。X の上のデスクトップ（GNOME の Xorg セッションなど）には自分の
WAYLAND_DISPLAY が無いので、既定の `wayland-0` を取ると、外で起動した GTK4 などの
アプリがすべて DEsk の中に開いてしまいます。DEsk の中から起動したアプリには
この名前が渡されます。

入れ子の窓には「DEsk」という名前、クラス `desk-window`、プロセス ID が付くので、
GNOME などのドックでは起動した項目のアイコンにまとまります。

### GNOME から開く

`~/.local/share/applications/desk-window.desktop` を置くと、アプリ一覧とドックから
開けます（この機械ではドックのお気に入りにも加えてあります）。中身は
`session/desk-window.desktop` と同じで、`Exec` をこのリポジトリの
`scripts/desk-window` にし、`StartupWMClass=desk-window` を付けたものです。
GNOME は標準ではデスクトップにアイコンを出しません。デスクトップに置きたいときは
拡張機能 Desktop Icons NG（`gnome-shell-extension-desktop-icons-ng`）を入れ、
`~/デスクトップ` の .desktop ファイルを「起動を許可」にします。

## 通知センター — 机の上のポスト

通知バナーはありません。**机の右奥に立っているポスト**です。

**DEsk 自身が通知デーモンです。** セッションバスの `org.freedesktop.Notifications`
を取るので、ここに届くのは本物 — 機械の上の全アプリケーションが「あなたに伝えている」
と思っているものです。`sd_bus` がファイル記述子をくれるので、コンポジタ自身のイベント
ループがそれを見ます。**別スレッドもロックもありません。** バスが無ければ箱が空のまま
動きます。

箱は**名札の文字が見える所まで**奥に置いてあります。投入口は**扉の頭（前面）**にあり、
真鍮の枠と雨よけの庇が付いています。真上からは庇が真鍮の帯に見え、その下に影が落ちます。
読んでいない手紙があると、**封筒がその口に差し込まれたまま手前に出ています**。一通ずつ
斜めに、長さを変えて（3 通まで重なる）、一番上の封筒には切手と宛名、下の一通は航空便の縁。
机に影を落とし、庇の下に入っている側は暗くなります。

置き場所は固定の座標ではなく**画面の上端の見通し線からの相対**にしてあります。
隠している縁は画面の縦横比で動く — 4:3 の机では四単位ぶん奥 — ので、固定値だと片方では
出しっぱなし、もう片方では埋まります。Control Panel の引っ込みしろを直したのと同じ罠です。
縁より奥は**そもそも描いていません**。

封筒は**寝かせて**出してあります。真上から見下ろすカメラでは、垂直に立った紙は線に
しかなりません — 旗を立てる案を捨てたのと同じ理由です。寝ていれば、それは手紙です。

クリックすると**箱の正面へ回り込み、扉が落ちて**中の手紙が見えます。扉が開くのは
移動の 42% から 96% のあいだ。着いてから開くのではなく、着きながら開きます。

箱の中の手紙は、**旧 iOS の Safari のタブのように**並んでいます。紙は箱の中に**立って**
いて、奥のものほど一段高く立つので、**全部の手紙の頭が見えます**。**ホイールで手紙を
めくれます**（1 ノッチで 1 通、ALL APPS のバインダーと同じばね）。めくった所の手紙は
まっすぐ立ち、**それより手前の手紙は前へ大きく倒れて**開いた扉の上に伏せ（紙の裏に、表の
字が透けて逆さに見える）、**それより奥の手紙は奥ほど強く後ろへもたれます**。伏せた手紙を
クリックすると、そこまでめくり戻します。

**どの手紙も、窓の紙と同じく右上の角が少し折れています。** 角の折り目にポインタを
載せると角が動き、そのまま置くかクリックすると角がめくれ上がって、**裏に印刷された操作**
が読めます。
- **Read** — 取り出して机に置く（手紙をクリックしたのと同じ）
- **Mark read** / **Mark unread** — 箱に入れたまま既読／未読にする（赤い消印が消える／付く）
- **Discard** — 角が大きくめくれて、手紙を捨てる（送り主には `NotificationClosed`）
- 送ってきたアプリが自分の操作を付けていれば（Reply、Archive など）、Mark の代わりに
  その一つ目が一番上に印刷されます。押すとアプリに `ActionInvoked` が届き、手紙は片付きます
  （`resident` のときは残って既読に）。操作が `default` だけなら **Open**。

奥の手紙の角（頭の右上）をクリックすると、そこまでめくって、その手紙の角が上がります。

DEsk は通知デーモンとして `actions` に対応していると答えるようになりました
（`GetCapabilities`）。

（見比べ用に、めくらない固定の並べ方も残してあります：`DESK_LETTERS=forward` で
「手前ほど前へ少し倒れる」、`DESK_LETTERS=back` で「奥ほど後ろへ倒れる」。）頭の一行目は**件名**、その下に `From` と**差出人のアプリ**、左に
アイコン、右に届いた時刻と未開封の赤い印。一番手前の手紙は、罫線の入った便箋に本文まで
読めます。紙と紙の間の狭い隙間は暗く、上の縁は光を受け、反った所はランプの方を向くので
明るく、奥の紙ほど暗くなります。アイコンは本棚でそのアプリの
紙に刷ってあるのと同じもの（`desktop-entry` ヒント、無ければアプリ名で引きます）。
一度に立っているのは 5 通まで、残りは「n more below」。

手紙をクリックすると、**封筒から紙が出てきて机の上に降ります。** 三つ折りの癖がついた
紙に、差出人・時刻・件名・本文。**そこに置かれたままになります** — 読んだ手紙もまだ
机の上の紙だからです。片付けるのはこちらがやることで、勝手に消えるものではありません。
持って引きずれば好きな所へ動かせ、置いた所に残ります。動かさずにクリックすると捨てられ、送り主には `NotificationClosed` が返ります。

`desk-preview --post` で箱だけ書き出せます（静止画のために手紙を数通入れてあります）。

## 解像度が変わったとき

追従します。ウィンドウを引き伸ばしても、画面のモードが変わっても、机はその寸法で
焼き直されます。

途中は焼きません。リサイズは端をつかんでいるあいだ毎フレーム飛んできて、その一つ
一つが**レイトレーサにとっては別の部屋**です。なので**落ち着くまで待ちます**
（350 ms）— 最後の一つだけが焼かれます。

丸めるのは**寸法ではなく形**です。縦横比を 1/32 に、幅を短い梯子に丸めます。これで
1440x900 のウィンドウと 3600x2260 の全画面は**同じ部屋**になります。以前は高さが
十数画素違うだけで別の部屋で、それぞれ一分半のトレースと 11 MB のキャッシュでした。
机は高さで画面に合わせ、幅は三割余らせてあるので、形の数 % の差は切り取り方の数 % の
差にしかなりません。

**焼き上がるまで、直前の部屋をそのまま出します。** これが以前いちばん困った点でした。
新しい形の部屋がまだ無いと `room_for()` は「無い」と答え、机は板になり、しかも
**当たり判定が全部消えました** — ポストも Control Panel も引き出しもドックのアイコンも。
一度も開いたことのない大きさにすると、一分半のあいだ机が死んでいました。

いまは形の違う部屋でも出します。足りないぶんは覆うまで拡大し、余りは下（どうせ切れて
いる手前側）で吸収するので、奥の縁 — 手が届かないと困るもの — は動きません。数秒後に
本物が焼き上がると入れ替わります。

部屋がひとつも無い本当の初回だけ、平らな机になります。

## 大きさはポイントで

机の上の物（Control Panel・時計・ポスト・ALL APPS の札）の大きさは、**画面の画素数では
なくポイントで決まります**。Mac と同じ考え方で、1 ポイントは普通の画面では 1 画素、
Retina のような高密度の画面では 2 画素です。**画面が大きくなると物が大きくなるのではなく、
机が広く見えます。**

以前は机が常に画面の幅いっぱい（机の単位で 32）で、物は画面に比例していました。1918×920 の
画面では 1440×900 のときの 1.33 倍、4K では 2.7 倍の大きさで、解像度の割に大きく見えました。

- 基準は設計した 1440×900 です。机 1 単位を 45 ポイントとし、机の幅を「画面の幅（ポイント）÷ 45」
  にします。1440×900 より狭い画面では物が入りきらないので、今までどおり部屋ごと縮みます。
- Control Panel は左の角、ポストは右の角に付いたまま、机と一緒に外へ動きます。時計は中央。
  部屋の照明（右手前のランプ）も机と一緒に動いて大きくなるので、広い机でも照らされ方は同じです。
- 帯（作業領域の上端）は、1x ならどの画面でも 80〜90 px ほどです（以前は 1918×920 で 147 px、
  3840×2160 で約 270 px）。ポストは札の「POST」の文字がちょうど見える所まで奥に置いています
  （上の蓋の投入口はやめました）。**投入口は扉の頭にあり**、真鍮の枠と、雨よけの庇が付いています。
  未読があると、そこから**紙が手前に突き出ています**（未読が多いほど長く、3 通以上なら 3 枚重なって
  見えます）。
- 倍率は `DESK_SCALE=2` のように指定できます（小数も可）。指定しなければ、画面が大きさ（mm）を
  報告していれば密度から決めます（144 dpi 以上で 96 dpi に対する比を 0.25 刻み、それ未満は 1）。
  入れ子（X11 や Wayland の窓の中）では 1 です。
- まだ倍率に合わせていないもの：窓の紙の余白と角、アプリ自身（DEsk は出力の拡大率
  `wl_output.scale` をまだ持たないので、高密度の画面ではアプリが小さく出ます）、本棚・
  Control Panel・ポストを見に行ったときの画面（画面いっぱいに映す眺めなので、画面に比例します）。

## 大きい画面で

画面が大きいほど部屋は**引き伸ばされます**。トレースは、C のトレーサだと 1440 幅まで、
**本物の GPU なら 1920 幅まで**で、あとは拡大です（レイトレースは面積に比例するので、
3600 幅を素で焼くと六倍かかります）。

1440 で頭打ちだったころは、1918 幅の画面だと部屋が 1.33 倍に伸ばされていて、同じ画面に
等倍で描いてある札や LED と並ぶと、机だけが柔らかく見えました（Retina なら伸ばされても
気づきませんが、等倍の画面では気づきます）。GPU のある機械では、部屋が画面の幅に付いて
いきます（1920 幅の GPU 実測で、机まで約 5 秒、全部で約 11 秒。キャッシュは 13 MB → 22 MB）。

- **どの機械かは覚えます。** 本物の GPU（`llvmpipe` などの CPU 上のラスタライザは数えません）が
  部屋を一度焼くと、キャッシュのディレクトリに `room-wide-<ビルド>.ok` を置きます。
  1440 より広い画面の最初の起動では、焼き始める前に GPU を開いて確かめ、本物なら
  最初から広い部屋を焼きます（以前は最初の起動を 1440 で焼き、次の起動で広い部屋を
  もう一度、机から焼き直していました。初回が二度あったのと同じです）。
- **GPU が無い日は戻ります。** 広い部屋を焼く必要が出たとき GPU が使えなければ、印を
  消して 1440 で焼きます（CPU で 1920 を焼くと四分近くかかります）。
- `DESK_ROOM_W=<幅>` — 幅を決め打ちにする（320〜3840。GPU の有無は見ません）。
  同じ部屋を取っておきたいときは、この値も揃えてください。
- **焼くのは画面を描いている GPU です。** GPU が二つあるノート（Intel と NVIDIA など）で、
  以前は最初に見つかった方を使っていたので、眠っている NVIDIA を起こしたり、クロックを
  上げられないドライバ（nouveau）の上で焼いたりすることがありました。いまは合成と同じ
  GPU を先に試します。どれで焼いたかは下の「困ったときのログ」の
  `desk: room: tracing on …` の行に出ます。`DESK_GPU_NODE=/dev/dri/renderD129` のように
  決め打ちもできます。

そのため、画面の座標で机に重ねて描くもの（ポインタの下の光だまり、Control Panel の
ランプと針、ガジェットのガラスの奥）は **2048 幅を上限**にして、あとはシーングラフに
拡大させています。3600x2260 での実測：

| | 以前 | いま |
|---|---|---|
| Control Panel の生の半分（毎秒 12 回） | 18.4 ms | 11.5 ms |
| ポインタの光だまり（動かすたび） | 8.5 ms | 2.8 ms |
| ガジェットの発光（毎秒 1 回） | 1.8 ms | 1.1 ms |
| 部屋を暗くする幕 | 32 MB | 1 KB |

**ALL APPS の札はポイントで**決まります（ポストと同じ扱い）。以前は画面の短辺に比例、
その前は 52 px で頭打ちで、3600 幅では 500 px のポストの隣に切手のような札が貼ってある状態
でした。

## 画面が二つ以上のとき

机があるのは一つの画面だけです（位置 0,0 の画面。表示の道具で並べ替えればそれに
なります）。ほかの画面には、**机の続きの板**が出ます。机の天板を、奥に立っている物の
下から引き出しの取っ手の上まで切り出し、机の画面の端から鏡に映すように継いで敷いた
ものなので、板目は画面の境で途切れずに続きます。机の画面から遠い側ほど暗く、ログインの
ときは机と同じくランプと一緒に明るくなります。本棚・Control Panel・ポスト・引き出しは
机の画面にだけあります。

- 窓は置けます。机の画面と同じ紙の窓で、角の Fold / Unfold / Discard もそのまま使えます。
- 新しい窓は**ポインタのある画面**に出ます（X11 のアプリが場所を指定したときはその画面）。
- Unfold（最大化）はその画面いっぱい、全画面もその画面いっぱいです。
- その画面で Fold（畳む）と、畳んだ紙は**その画面の手前**に置かれます。クリックで開き、
  運んで離せば離した所に置けます（引き出しにしまう設定のときは引き出しへ）。
- 机の画面で引き出しを出したり、本棚・Control Panel・ポストに向き直ったりしても、
  ほかの画面の窓と畳んだ紙は動きません。本棚などを見ているあいだも、ほかの画面の窓と
  紙には手が届きます。引き出しが出ているあいだに、ほかの画面をクリックすると引き出しが戻ります
  （机の画面で、引き出しより上をクリックしたときと同じです）。
- 画面を外したり、表示の道具で消したりすると、そこにあった窓は残った画面の近い所へ、
  畳んだ紙は残った画面の手前へ移ります。最大化・全画面だった窓は、移った画面に合わせます。
- 机の画面より大きく描くもの（部屋、引き出し、向き直るときのフィルム、本棚に寄るとき）
  は、机の画面の分だけに切って描くので、隣の画面にははみ出しません。
- タッチパネルのように「どの画面のものか」を名乗る入力機器は、その画面に合わせます。
- 画面ごとのフレームの仕事（紙・アニメーション・時計）は、画面がいくつあっても
  一フレームに一回です。

## 引き出しは閉じた状態で始まります

引き出しを開けると、机は**引き出しの高さぶん持ち上がります**。持ち上がった机の奥の縁は
画面の外に出ます。そこにあるもの — Control Panel、ポスト、システムトレイ — は
見えないだけでなく**押せません**。以前は開いた状態で起動していたので、最初にポストを
押した人には何も起きませんでした。

いまは机として始まります。引き出しは Super+D か真鍮の取っ手で開きます。

## 引き出しの中身

引き出しには、**入れたものが入っています**。最初は 5 つの小物 — ポケットコンピュータ
（画面にプロンプト）・真鍮の方位磁針・マニラフォルダ・メモ帳と鉛筆・ドライバー。
**DEsk の標準のプログラム**の端末・ブラウザ・ファイルマネージャ・テキストエディタ
（下の「標準のプログラム」）と、Shell Settings です。小物はアプリそのものではなく
**役目**を指していて（`thing terminal` など）、標準が変われば開くものも変わります。

- **クリック**で使います。アプリは起動し、ドライバーは Shell Settings を開き、折りたたんだ紙は
  机の上に上がって広がります。引き出しは閉まります。
- **ドラッグ**で並べ替え。運んでいる間、入る場所が空いて待っています。
- **机の上へ運んで離す**と、アプリは引き出しから抜けます（薄くなって消えます）。
  ドライバー（Shell Settings）だけは抜けず、元の場所に戻ります。
- **最小化した紙**は、**右ボタンでドラッグ**すれば机の上の好きな所へ動かせます（左の
  ドラッグでも動きますが、左はクリックすると窓に戻ります。右はクリックしても何も起きず、
  取っ手まで運んでも引き出しは開きません）。机の上から引き出しへ運んで入れることもできます。閉じた引き出しの取っ手まで
  運ぶと、引き出しが出てきます。引き出しの中の紙は、机の上へ運び出せば離した所に置かれます。
  窓が終われば、紙も引き出しから消えます。
- **ALL APPS のバインダーの紙**は、窓や手紙と同じく右上の角がめくれます。裏には `Open` と
  `Into the drawer`（入っていれば `Out of the drawer`）。
- ポインタを載せた物は少し浮いて、名前がフェルトにチョークで書かれます。

小物は一つの種類につき一つです。同じ種類の 2 つ目（端末を 2 つ入れたなど）と、種類の
無いアプリは、アイコンを刷った**カード**になります。数が増えると列が詰まり、収まらなく
なると一つ一つが小さくなります（32 まで）。入れたアプリと順番は
`$XDG_CONFIG_HOME/desk/drawer`（`app <desktop id>` と `panel` の行）に残ります。
折りたたんだ紙は残しません。窓が終われば消えるものなので。

中身は焼いた部屋の一部ではありません。引き出しは**空で**焼き、中身は置いた所に描いて
重ねます。小物は真上から見た平らな物として描いてあり（以前はトレースした小さな立体模型で、
フェルトから浮いた「アイコン」に見えました）、部屋のランプの向きで陰影が付き、影は
**接地の濃い影**と、**厚みの分だけ伸びるランプの影**の 2 つ。フェルトの明るさを
その場所で測って、端に置いた物はそのぶん暗くなります。フェルトの大きさの 1 枚に描いて
引き出しシートと一緒に動かすので、開閉は今までどおりノードを動かすだけ、並べ替えで
滑っている間も 1 コマ 1 ms ほどです（小物の絵は一度描いて取っておきます）。

引き出しは**画面の約 2 割**まで出ます（以前は約 3 割）。開いている間、机は引き出しの高さ
だけ持ち上がり、**窓と折りたたんだ紙も一緒に上がります**（以前は窓だけ元の場所に残って、
引き出しの下に隠れていました）。開いている間に机をクリックすると、引き出しは閉まります。

## 机が先、ほかは後

トレースは全部で一分半ありますが、**そのうち机は一割**です。残りは本棚・Control
Panel・ポストと、その三つのカメラ移動のフィルム（18 コマ × 3）で、**どれも起動直後の
画面には映っていません**。

なので三段に分けました。

1. **机の二枚が焼けた時点で机を出します。**
2. 次に**本棚・Control Panel・ポストの絵を一枚ずつ**焼き、**一枚焼けるごとに、その眺めが
   使えるようになります**。本棚（アプリはそこにあります）が最初です。以前は三枚そろうまで
   どれも開けず、GPU の無い古い機械では、それが机が出てからさらに十数分でした。
3. 最後に、**そこへ向き直るカメラの動きのフィルム**を焼きます。フィルムは 18 コマで、
   眺めの絵一枚の半分（Low）から 4.5 倍（Ultra）の手間です。以前は絵とフィルムを
   眺めごとに交互に焼いていたので、時計の `SHELF` の間にフィルムまで待たされ、
   Ultra では本棚が出るまでに本棚の絵の 5.5 倍かかっていました。フィルムができるまでは、
   眺めへの移り変わりは 2D と同じ切り替えです。できたものから一本ずつ動きが付きます。

この VM の GPU で Ultra を初めて焼く実測（1440 幅にそろえて前後を比較）で、眺めがそろうまで
机が出てから **13.1 秒 → 1.6 秒**、明かりが上がりきって `READY` まで 22.8 秒 → 10.8 秒。
フィルムはその後ろで 10 秒ほど焼いています。GPU の無い 2010 年ごろ相当（Low）では、本棚が
使えるのは机の 14 分後です（以前は Control Panel・ポストの絵と 2 本のフィルムも待って、
30 分を超えていました）。CPU では本棚と Control Panel の絵が机の 3〜4 倍重く、GPU の無い
機械の初回はここが次の課題です。

裏で焼いているあいだ、まだ絵の無い眺め（ALL APPS の札・Control Panel・ポスト）は
**返事をしません**。振り向いた先がまだ無いからです（板張りの空間が出るくらいなら、
札が反応しないほうがよい）。机のほうは最初から普通に使えます。焼いたものは一枚ずつ
キャッシュに保存するので、フィルムを焼いている途中でログアウトしても、次は机と眺めを
読み戻して、残りのフィルムだけを焼きます（書きかけのファイルは残しません）。

## ログイン — 明かりがつく

ログインすると、部屋は**暗いところから**始まります。見えるのは机の奥の時計だけで、
赤い LED が**部屋の支度がどこまで進んだか**を数えています（`DESK` → `SHELF` →
`PANEL` → `POST` → `LAMP` と、横のブロックと大きな % の数字）。数えるにつれて
**デスクライトが少しずつ上がり**、光はランプの下の光だまりから先に、温かい色で
広がって、部屋の隅が最後に明るくなります。100% で `READY` と出て、時計は時刻に
戻ります。

- % は本物の進み具合です：机の二枚（45%）、本棚・Control Panel・ポストの絵
  （40%、一枚ずつ）、最初に見るときのための先回りの絵（15%）。カメラの動きの
  フィルムは数えません（待つ人がいないので、眺めの絵の後で焼きます）。
- **明かりは机が出たらすぐ上がります**：1 秒で（Low は 0.5 秒。「動きの速さ」で
  前後します）。本棚などの残りを待たず、明るい中で時計がそれを数え続け、終わると
  `READY`。部屋がキャッシュから読めれば、明かりがつくまで 1 秒ほどです（以前は最低
  3.6 秒、本棚などの遅い機械ではさらに 12 秒、暗いまま待っていました）。
- 待つものは何もありません。暗い間も机は普通に使えます。
- 机がまだ一度も焼かれていないとき（そのサイズの初回）は、進み具合は**上の時計**が
  言います。時計の置き場所は部屋のカメラの寸法だけで決まるので、机ができる前から、
  その場所で暗がりに光って数えます。GPU の準備で数え始められない数秒も、机の分の
  3 割までゆっくり進みます。
- **GPU で焼けない機械では、先に「ひと目」を出します**：机を 3 分の 1 の大きさ・
  1 画素 1 サンプルで先に焼き（全体の 36 分の 1 の手間）、ぼかして引き伸ばした机を
  数秒で出して明かりを上げます。本物の机はその後ろで焼き続け、できたら入れ替わります。
  2010 年ごろの機械を真似た条件で、暗い画面が 94 秒から 6 秒になりました。
- 部屋は**更新しても焼き直しません**。キャッシュの鍵が部屋の見た目（`room.glsl` の
  ハッシュ）だけで決まるからで、焼き直すのは部屋の見た目が変わった更新のときだけです。
- 要らなければ Shell Settings の「ログイン時にゆっくり明かりをつける」を切ります
  （`shell.conf` の `lights_at_login = no`）。最初から明るく、時計は数えるだけです。

## 支度中の机

初回は板だけの机しかありません。暗いまま、**上の時計が光って数えます**（上の
「ログイン」）。机の分はトレーサが済ませた**走査線の本数**そのもので、机の分が数え
終わった瞬間に机が出ます。GPU で焼けない機械では、その前に小さく焼いた「ひと目」の机が
出ています。

そして机の真ん中に**手紙が一通**置いてあります：「机を用意しています ― 初回起動時は
時間がかかるかもしれません。環境によっては 1 分から 2 分以上かかることも有ります。その間も
机は使えます。本棚・Control Panel・ポストは、用意ができたものから開けます」。部屋を
キャッシュから読めず一から焼くとき（その画面の大きさ・段階で初めてのとき）だけで、暗い
間は暗がりの上に、明かりがつけば机の上（窓の下）に置かれ、本棚・Control Panel・ポストが
そろうと片付けられます。触っても何も起きません（下の机がそのまま応えます）。画面の解像度で
描くので、2D でも字がつぶれません。

焼いている間も机は滑らかに動きます。トレーサのスレッドは **nice 19**（後回し）で走り、
机とプログラムが使わない分の CPU だけを使います。以前は 2 コアの機械で、トレーサの
2 本と机が同じ優先度で取り合い、焼いている間じゅう机が重くなっていました。

リサイズがトレース中に降ってきたときは断られます。以前はそれきり誰も取りに戻らず、
**机が板のまま二度と直りませんでした**。いまは支度中のあいだ 400 ms ごとに焼き直しを
頼み直すので、断られた分は次で通ります。

## GPU で焼く

部屋のレイトレースは、**GPU があれば GPU で**走ります。`src/room.glsl` は `draw.c` の
トレーサ（`scene_map`・素材・`shade_surface`）を一行ずつ移したもので、**正解はいつも
C のほう**です。片方を変えたら、もう片方も変えます。

- 要るのは **GLES 3.0 と 32 ビット浮動小数の描画先**（`GL_EXT_color_buffer_float`）
  だけで、それより新しいものには頼りません。VMware の仮想 GPU（SVGA3D）は 3.0 で
  止まっていて、3.1 を要求していた頃は、そこで GPU が無いことにされていました
- **一本のシェーダでは渡しません。** 部屋を丸ごと一つのプログラムにすると、SVGA3D は
  リンクの途中で落ちるか、**何も描かない代わりのシェーダを黙って**走らせます。そこで
  **4 本のプログラム・5 回のパス**に切り（当たり → 素材 → 見えるもの → 映り込みの
  素材 → 光）、途中の値は 32F のテクスチャで渡します。float32 のまま運ぶので、切っても
  絵は変わりません
- 描くのは**窓ごと**です。一回の描画が長いと GPU の番犬がカードを、VM ならホストが
  ゲストをリセットします。窓は小さく始めて、速いあいだだけ広げます
- **信用しません。** 焼いた一枚ごとに 192 サンプルを C で引き直して突き合わせ、一割
  以上食い違えば、その層（机・本棚・Control Panel など）はそのプロセスではもう C が
  焼きます。二つ目の層が食い違えば、その GPU はもう使いません。非有限値が混じって
  いても同じです
- **初めて会うドライバは、子プロセスで試します。** プログラムを受け取れないドライバは、
  そう言うことになっています。言わずに落ちるものもあります（SVGA3D が実際にそうでした）。
  コンポジタが落ちればセッションが落ちるので、ビルドとドライバの組ごとに一度だけ、同じ
  実行ファイルを子として起こしてプログラムを作らせ、机の隅を焼いて検算させます。落ちても、
  固まっても（2 分なにも言わなければ殺します。プログラムを作るのが遅いだけのドライバは、
  一本作るたびに言うので殺されません）、描き間違えても、親は C で焼くだけです。結果は
  `~/.cache/desk/room-gpu-*.ok` / `.bad` に残り、`.bad` には**落ちた理由**（シェーダの
  エラー、何サンプル食い違ったか、どこで落ちたか・黙ったか）が入ります。ログにも
  `desk: room: … failed its trial: <理由>` と出ます。消せば聞き直します
- **CPU で焼くときの Ultra は High の部屋です。** 1 画素 9 サンプルと半分の大きさの
  フィルムは GPU 向けで、試運転に落ちた GPU の代わりに CPU が Ultra を焼くと、ある
  ノート（Tiger Lake・8 スレッド）で眺めがそろうまで 12 分かかりました。CPU が焼く
  機械では、Ultra を選んでいても High と同じ部屋を焼いて使います（のちに GPU が焼ける
  ようになれば、Ultra の部屋はそのとき GPU が焼きます）
- GPU の無い機械では、Mesa の **llvmpipe**（CPU で動くラスタライザ）がこの役をします。
  それでもシェーダは何ピクセルもまとめて計算するので、C トレーサの **10〜16 倍**の
  速さで焼けます

1440x900 の初回（机・本棚・Control Panel・ポスト・フィルム 54 コマ）を、この VM
（VMware SVGA3D、8 コア）で焼いた時間:

| | 時間 |
| --- | --- |
| C トレーサ | 155 秒 |
| GPU | 7.7 秒（そのドライバと初めて会うときは、試行込みで 9.3 秒） |

焼き上がりは、1440x900 のプレビューで 99.8% の画素が C とまったく同じで、1% を超えて
違う画素は一つだけです。

どのデバイスで焼いたか、なぜ C に戻ったかは、標準エラーに `desk: room:` で一行
出ます。

- `DESK_NO_GPU=1` — GPU を使わない。すべて C が焼きます
- `DESK_ON_CPU=1` — 画面を CPU が描いているものとして扱う（2D フォールバックと手紙。
  `0` でその逆）
- `DESK_GPU_NODE=/dev/dri/renderD129` — 最初に試す render node
- `DESK_GPU_DUMP=/tmp/room` — ドライバに渡したシェーダを `/tmp/room.1`〜`.4` に
  書く（不具合の報告に）
- `DESK_ROOM_GLSL=src/room.glsl` — 組み込みのシェーダの代わりにファイルを読む
  （作業用。このときは試行の結果を残しません）
- `DESK_ROOM_W=1920` — 焼く部屋の幅（既定は C なら 1440、本物の GPU なら 1920）
- `DESK_SCALE=2` — 1 ポイントの画素数（「大きさはポイントで」）

初めての機械では、GPU と C をまるごと突き合わせられます:

```sh
./build/desk-gputest --room 480 300 /tmp/room-check
```

シートの種類ごとに両方で焼き、サンプルと画素の食い違いを表にして、GPU・C・差分の
PNG を `/tmp/room-check` に書きます。

## 紙の角 — ウィンドウの操作

窓にはボタンもタイトルバーもありません。窓は紙で、題名は紙の上端に印刷された見出しです。
操作は**右上の角**にあります。どの紙も角が少しだけ折れています。その折れにポインタを
乗せると角が少し浮き、**そのまま 0.5 秒**置くか**クリック**すると角が柔らかく持ち上がって、
**紙の裏に印刷された指示**が読めます。角の近くを通り過ぎただけでは開きません（右上に
ボタンを置くアプリの邪魔をしないため）。持ち上がった角は、ポインタが裏の上にある間は
開いたままです。

- **Fold** — 角をさらにめくってから、紙を実際に折りたたんで机の手前に置く（最小化）
- **Unfold** — めくれを平らに戻しながら紙を広げる（最大化）。広げた紙では **Refold**
- **Discard** — 角を大きくめくってから閉じる。アプリが保存の確認を出して閉じなかった
  ときは、角は元に戻る

### 大きさを変える

紙の残りは、端で紙の下に折り込まれています。

- **端を引く**（カーソルが矢印に変わる所）と、紙はすぐにポインタについてきて、端で後ろへ
  回り込む折り返しから紙が出てきます。最初の折り目は引いている間は山のように盛り上がり、
  手を離すと少しだけ跡を残して寝ます。出てきた紙には、畳まれていた折り目が残っています。
  アプリが新しい大きさで描き直すと、折り目はその下に隠れます。
- **端を押し込む**と、中身は紙の端で後ろへ折り込まれて見えなくなります。
- 左端や上端を引いている間、アプリの描いた中身は反対側の端に寄ったまま動きません。
  強く引くほど端の折り返しが丸くなり、手を離すと平らに落ち着きます。
- **Unfold**（最大化）は、山折りにして裏へ畳んであった紙を開く動きです。紙の縁が手前へ
  反り上がって山になり、その下から畳まれていたパネルが起き上がって、先を机に付けたまま
  外へ倒れ、平らになります。左右、次に上下の順です。持ち上がった所は手前に来るので
  少し大きく見え、ランプに向いた面は明るく、反対の面は陰になり、机に影を落とします。
  広がった紙には開いた所の折り目が残り、アプリが描き直すまでは、その折り目と元の中身が
  そのまま見えています。
- **Refold** では逆に、上下、次に左右の縁が山になって、パネルが中身ごとその下へ折り込まれ、
  元の大きさに戻ります。

自分で枠を描くアプリ（GTK など）は、今までどおりアプリの枠で大きさを変えます。

### 折りたたむ

紙は、折り目の手前から先に曲がり、端が遅れて追いつくように折れます。持ち上がった所は
手前に来るので少し大きく見え、ランプの向きで明るさが変わり、下の紙に影を落とします。
半分を越えると見えるのは紙の裏です。大きい紙は 3〜4 回、小さい紙は 1〜2 回、はがきほどの
大きさになるまで折ります（ちょうど半分には折れません）。

折り上がった外側には、**アプリのアイコンと、その下にアプリの名前**が印刷されています。
机の手前に左から並び、クリックすると元の位置へ戻りながら広がります。置いた紙束は
**ほかの窓の下**になります（机に置いた紙なので。折っている間と広げている間だけ上）。
窓に隠れた所をクリックすれば窓に届き、紙束は窓をどければまた見えます。アイコンは
アプリの .desktop（app_id、X の WM_CLASS、StartupWMClass、実行ファイル名の順で照合）
から引き、無ければ名前の頭文字を刷ります。

### 捨てる

窓が閉じると、その紙は**その場でくしゃくしゃに丸められ（0.42 秒）、近い方の机の端へ
放り投げられます**。丸めるときは紙の縁から先に寄せ、表と裏の切れ端が入り混じった紙の球に
なります。投げた球は回りながら上がり、少し大きく見え、影が後ろに離れていきます。
Discard や Super+Q だけでなく、アプリが自分で閉じた窓（GTK の × ボタン、終了メニュー）も
同じです。wlroots が窓の最後の絵を手放す直前に写し取っています。

めくれて空いた所には、その下にあるもの（机、下の紙とその中身）が見えます。
自分で枠を描くアプリ（GTK など）と全画面の窓には角がありません（アプリ自身の
ボタンがそこにあるため）。キーでの操作（Super+M、Super+Q など）は今までどおりです。

## 机の奥の帯 — ウィンドウはここに乗らない

机の奥に並ぶもの — Control Panel、時計、ポスト、ALL APPS の札 — は、
**システムトレイと同じ扱い**です。窓はこの帯に乗りません。

- 帯の下端は、焼いた部屋から画面の大きさごとに測ります（1440×900 で約 130 px）。
- 新しい窓は帯の下に出ます。タイトルバーを帯の中へ引き上げても、下端で止まります。
  上の辺でのリサイズも同じです。
- 最大化は、帯の下から、引き出しの取っ手の帯（画面の下端）の手前までです。
- 位置を指定する X11 のアプリも、帯の下に下ろします。X には `_NET_WORKAREA` で
  使ってよい範囲を伝えます。
- 画面の大きさが変わったときや、部屋が焼き上がって帯の位置が決まったときは、
  帯にかかった窓を下ろし、最大化した窓を新しい範囲に合わせ直します。
- 全画面の窓だけは、帯も含めて画面全体を覆います。
- 引き出しを開けている間は、机ごと帯も上に動きます（これまでどおり）。机の上の窓と
  折りたたんだ紙も一緒に上がります。

## 時計

机の奥の時計は、赤い LED の表示窓と、その右に **2×2 の 4 つのキー**があります。キーには
役目が印字されています。

```
| 表示窓                    | CLOCK | DAY   |
|                           | MEDIA | POWER |
```

- ポインタが時計に**近づくとキーの文字が琥珀色に灯り**、指したキーは光が漏れて少し
  浮き上がります。押すと沈みます。
- キーを押すとそのページが出て、キーの中のランプが点きます。ふだんの時刻の画面は
  **CLOCK** のページで、そのランプが点いています。DAY・MEDIA・POWER のキーはもう一度
  押すか CLOCK を押すか、ポインタが離れて 12 秒たつと CLOCK（時刻）に戻ります。
- 表示は本物の LED のように描いています。数字は 7 セグメント、文字は 14 セグメント、
  小さな文字は 5×7 のドットで、点いていないセグメントも暗く見えています。

| ページ | 表示 |
| --- | --- |
| CLOCK（普段の時刻） | 大きな時刻（コロンが 1 秒ごとに点滅）。その右に小さく 2 段で、上に**カメラとマイクのランプ**（そのデバイスがある機械だけ。**使っている間だけ点灯**）、下に**秒**。さらに右に小さな音量（入力メソッドはトレイに出ます）。**電池のある機械では電池残量**（充電中は稲妻、10% を切って放電中なら点滅）、**画面の明るさを機械が持っている機械（ノート PC）では明るさ**を、その下の段に出します。どちらも無いデスクトップでは今までどおり 1 段です |
| DAY | 時刻の所が日付になります。例：`SEP/28/2026`（14 セグメント、0 は斜線入り） |
| MEDIA | いま再生中のもの（下の表）と音量 |
| POWER | 電池があれば残量・充電／放電・残り時間・W。電源につないだデスクトップでは、今の消費電力（NOW）、DEsk を起動してからの平均（AVG）、この 1 時間の電力量（Wh） |

普段のページと MEDIA ページでは、ホイールで音量を変えられます（±2%）。

**MEDIA** はオーディオ機器の表示窓のつもりです。再生しているアプリ（ブラウザ、Spotify、
VLC、Rhythmbox など、MPRIS に対応するもの）の様子を映します。

| 段 | 表示と操作 |
| --- | --- |
| 1 段目 | 曲名。表示窓の幅いっぱいのドットマトリクスで、入りきらなければ 2.5 秒止まってから流れます。アクセント付きの文字や全角英数は普通の英字にして出し、日本語などドットで書けない曲名はフォントで同じ色に光らせて流します。**クリックでそのアプリの窓を前に出します**（アプリが対応していれば） |
| 2 段目 | アーティスト（左）と経過／全体の時間（右）。**一時停止中は経過時間が点滅**します。停止中は `STOPPED` |
| 細い帯 | 曲のどこまで来たか |
| 3 段目 | **前の曲・再生／一時停止・次の曲**（押せないものは暗いまま。ポインタを載せると枠が灯る）、アプリの名前、スピーカー（クリックでミュート）と音量（**クリック・ドラッグ**で 10% 刻み） |

アプリが複数あるときは、再生中のもの（いちばん最近再生を始めたもの）、無ければいちばん
最近動いたものを映します。ボタンを押したアプリは一時停止してもそのまま映ります。何も
無ければ `NOTHING PLAYING` と出て、音量だけ操作できます。

**明るさ**は `/sys/class/backlight` から読みます（firmware → platform → raw の順に選ぶのは
logind やデスクトップと同じ）。Control Panel の BRIGHT のつまみは DEsk の中の「部屋の
明かり」で、画面のバックライトとは別物です。

**電力**は、測れるものだけを出典付きで表示します。電池で動いているときは電池から出る
電力がそのまま機械全体です。電源につないでいるときは、CPU の RAPL（多くのカーネルでは
root しか読めません）と、自分の電力を報告する GPU（amdgpu など）の合計で、表示の下に
「MEASURED: CPU+GPU」のように何を測ったかを書きます。何も読めない機械（この VM など）
では「NOTHING HERE MEASURES THE POWER」と表示し、数字は作りません。

## システムトレイ — Control Panel の下の紙片

アプリがトレイに出したもの一つにつき、**付箋ほどの紙片が一枚**、Control Panel の
本体と机の間に挟まっていて、アプリのアイコンが印刷された端だけが見えています。
場所は真鍮プレートの右、以前は回線のランプがあった所です。

- 並びは出てきた順です。並びきらないときは、右端に**次の一枚の端**が薄れて覗いていて、
  紙片の上で**ホイールを回すと列が横に送られます**（一目盛り一枚。送った分はプレートの
  棚の下に入ります）。
- ポインタを載せると、その紙片が少し引き出されて、ほかの紙片の上に来ます。
- 通知を求めている項目（NeedsAttention）は**少し長く出ていて、赤い印**が付いています。
  休止中の項目（Passive）は奥に押し込まれています。
- アイコンは紙に刷ったように描きます。白一色のような「形だけ」のアイコン（暗いパネル
  用に白で描かれていることが多い）は、そのままでは紙に写らないので、**形をインクで**
  刷ります。
- 机の奥の隅はランプの光の縁なので、紙片も机と同じだけ暗く見えます。

| 操作 | 動作 |
| --- | --- |
| クリック | アプリ自身の動作（たいていはウィンドウが出る） |
| 中クリック | アプリの副動作 |
| 右クリック | **紙片を引き出す**：紙片はカードの端に貼ってあり、カードが本体の下から出てくる |
| ホイール | アプリへ（並びきらないときは、列を送る） |

メニューしか持たないアプリは、どのボタンでもカードが出ます。

**カード**にはアプリのメニューが刷ってあります。

- 本体の下から滑り出て（引き出しと同じばねで、少し行き過ぎて止まる）、机の上の紙
  （ウィンドウ）より上に来ます。出てくる途中は、台座の下とプレートの棚の下の両方から
  出てくるように見えます。
- 頭にアプリのアイコンと名前、赤い罫、その下に項目。チェックは鉛筆の印、ラジオは丸、
  区切りはミシン目、使えない項目は薄い字、サブメニューは「›」。
- 項目にポインタを載せると鉛筆の下線。クリックでその項目を選び、カードは本体の下に
  戻ります。サブメニューは同じカードに降りて、頭の「‹」で戻ります。頭のアプリ名を
  クリックするとアプリが出ます。
- キーでは ↑↓ で項目、Enter で選ぶ、→ でサブメニュー、← で戻る、Esc でしまう。
  カードの外をクリックしてもしまいます。長いメニューはホイールで送ります。
- メニューを持たないアプリのカードには「Open」だけがあります。

対応しているのは StatusNotifierItem と、そのメニューの dbusmenu です（KDE・Qt・
Electron・libappindicator 系のアプリ、fcitx5、nm-applet --indicator など）。セッション
バスに watcher がいなければ DEsk がなり、別のデスクトップの中で動かしていてそちらに
watcher があれば、そちらに問い合わせます。

まだ無いもの：X11 の XEmbed トレイ。

## ウィンドウの枠

紙の枠（明朝の見出しと罫）を付けるのは、枠を DEsk に頼むアプリです。頼み方は
二通りあります：xdg-decoration（Qt・KDE のアプリ、foot など）と、GTK 3 が使う KDE の
server-decoration（`org_kde_kwin_server_decoration_manager`、DEsk の既定は「サーバー
側」）。だから Xfce・MATE のアプリ（xfce4-terminal、Mousepad、Pluma、Ristretto、Atril、
Engrampa、Parole、Eye of MATE など）は、GTK のタイトルバー無しで紙に載り、見出しが
付きます。自分でタイトルバーを作る窓（ヘッダーバー。GNOME ディスク、GTK のファイル
選択、Firefox）は「自分で描く」と言うので、自分の枠のまま紙の余白に載ります（下の
「自分で枠を描くアプリも紙に載せる」）。窓が出た後で言うことが変わっても、枠はその場で
決め直します。限界：GTK 3 で装飾を消した窓（スプラッシュなど）も「サーバー側」と言う
ので見出しが付きます（KWin でも同じ）。X11 のアプリは、自分で枠を描くもの以外に
付けます。

## X11 のアプリ（Xwayland）

Wayland に対応していないアプリ — 古いアプリ、多くのゲーム、Electron 製の一部 — も
開けます。X11 のアプリには Xwayland という X サーバーが要りますが、**最初の X11 アプリが
接続したときに初めて起動します**。使わなければ何も動かず、何も消費しません。

- DEsk は自分の子プロセスに `DISPLAY` を渡します。入れ子で動かしているときも、外の
  X（`:0`）ではなく DEsk の中の Xwayland（`:1` など）に開きます。
- X のウィンドウも **Wayland のものと同じ紙**になります。枠、影、移動とリサイズ、
  最大化、折りたたみ（中身ごと写ります）、閉じるボタン（`WM_DELETE_WINDOW`）が使えます。
- メニュー、ツールチップ、コンボボックスの一覧（override-redirect や、その種類の窓）は、
  アプリが指定した位置に、枠を付けずにすべての窓より上に出ます。
- 自分でタイトルバーを描くアプリ（Motif ヒントで枠なしを求めるもの）とスプラッシュ画面は、
  枠を付けずに影だけ付けます。移動とリサイズは、アプリからの `_NET_WM_MOVERESIZE`
  要求で行います。
- ダイアログは親ウィンドウの上に出します。`-geometry +X+Y` のように位置を指定された窓は
  その位置に出します。画面より大きいサイズを求められたときは、画面に収まるように縮めます。
- 全画面（F11 など）は、枠と影を外して画面全体を覆います。戻すと元の紙に戻ります。
- コピー＆ペーストは X と Wayland のあいだでも通ります。選択して中クリックで貼る
  primary selection も同じです。
- ドラッグ＆ドロップは、Wayland 同士、X 同士、Wayland → X で動きます。**X → Wayland は
  動きません**（wlroots 0.18 の Xwayland が対応していません）。その向きのドラッグは、
  放した所で何も落とさずに終わります。
- Xwayland が落ちても DEsk は落ちません。次の X11 アプリが接続したときに起動し直します。
  起動途中で落ちたときは作り直します（1 分に 3 回まで）。

使いたくないとき:

```sh
DESK_NO_XWAYLAND=1 desk-session       # 実行時に使わない
meson setup build -Dxwayland=disabled     # 最初から組み込まない
```

ログインセッション（`desk-session`）では、GTK・Qt・SDL に「Wayland を先に試し、
だめなら X11」と指定しています（`GDK_BACKEND=wayland,x11` など）。

**VMware の仮想 GPU（vmwgfx）の場合:** wlroots は、クライアントから受け取った GPU
バッファ（dmabuf）を検査するとき、ハンドルを一度取得してから閉じます。vmwgfx はこの
閉じる操作を受け付けません。そのままでは、Xwayland を含め GPU で描くクライアントがすべて
切断されます。DEsk は起動時に自分のバッファで一度だけこの検査を試し、同じ失敗をする
ドライバでだけ検査を省きます（ログに `this GPU cannot close a shared buffer's handle`
と出ます）。

## 起動まわり

**同時にひとつだけ**です。二つ目を起動しようとすると、断ってログにそう出します
（`XDG_RUNTIME_DIR/desk.lock` の `flock`。プロセスがどう死んでもカーネルが錠を
外すので、消し忘れた錠が残りません）。わざと二つ動かしたいときは
`DESK_ALLOW_MULTIPLE=1`。

これが要る理由は部屋がレイトレースだからです。**キャッシュが冷えた初回は、GPU が
無ければ機械の全コアを一分**使います。デスクトップのショートカットをダブルクリックすれば、それが
二本同時に走ります — 五コアの機械に十コア分の仕事が乗り、画面全体が固まり、しかも
最後に同じキャッシュファイルを二つのプロセスが取り合って書きます。二回目以降は
**0.3 秒**でウィンドウが出ます。

**ウィンドウを閉じれば終了します。** 入れ子で動かしているとき、ウィンドウはそのまま
出力なので、閉じたのにコンポジタが残っていると — 見えず、wayland ソケットを掴んだまま、
「機械が止まった」のと区別がつきません。

## 音

机の上の物は、それぞれの音を立てます。**録音はひとつもありません**。どの音も、その物が
音を出す仕組みのとおりに、その場で作っています（`src/sfx.c`）。

- 叩かれた物は、その物に固有のいくつかの周波数で鳴り、それぞれの速さで消える
  （木は低く短く、鋼は高く長く、プラスチックのキーは高く一瞬）
- こすれる物、離れる物は、その物の色をつけた雑音（引き出しのランナーは木目のざらつき付き）
- 紙は近くで聞くと、繊維がはがれる**細かいパチパチの雨**と、紙が押しのける空気の音
- 蝶番は「くっついて滑る」の繰り返し（キィ）、真空管の機械は電源のハムと、落ちていく
  高い音と、冷えるガラスのチッという音

どの音も数通りずつ作ってあり、鳴らすたびにそのどれかを、わずかに高さと大きさを変え、
画面の左右の位置に合わせて振り分けて鳴らします。同じ音が二度と同じには鳴りません。

| 広げる | 折り目がはがれる音と、開く折り返しの音 |

| 引き出し | ランナーを滑る音（動いている間だけ）、止まりに当たる音と中の物がずれる音／奥に当たる音。中の物を持ち上げる・置く音 |
| ALL APPS | バインダーを抜き出す音、机に開いて置く音とリングの鳴り、紙がリングを越える音（1 枚ごと）、紙を外す音、机に置く音、広がる音 |

**どこへ鳴らすか**：サウンドサーバへ、PulseAudio のクライアントライブラリで（PipeWire も
この言葉で答えます）。サウンドサーバが無ければ ALSA の既定の出力へ（ライブラリは実行時に
読むので、ビルドにも実行にも必須ではありません）。どちらも無ければ鳴りません。
`DESK_SOUND=off|pulse|alsa|file:PATH` で選べます（`file:` は聞こえるはずの音を実時間で
WAV に書く、試験用。`%p` はプロセス番号）。ビルドは `-Dsound=disabled` で libpulse を使わずに
作れます。

**音と絵を合わせる**：音は鳴らしてから聞こえるまでに、サウンドサーバとサウンドカードの
バッファの分だけ遅れます（ふつうの PC で十数 ms、仮想マシンでは 0.1 秒近く）。DEsk は
これを詰め、残りは先回りします。

- ストリームを 4 本（レーン）持ち、新しい音は**無音しか入っていないレーンに、サーバが
  読んでいる位置のすぐ先へ**書きます。溜めてある無音の後ろに並べないので、重なった音も
  待たされません。
- レーンは最後の音から 0.5 秒で止め、サーバとカードを休ませます。カードの具合が良ければ
  `DESK_SOUND_AWAKE_S=8` で「キーやポインタが動いてから 8 秒は止めない」にでき、
  間を置いた最初の音が数 ms 早くなります（既定で切ってあるのは、下の仮想マシンのように、
  カードを動かし続けると砂嵐のような音がする環境があるため）。
- **動きの終わりの音は先回りして**鳴らします。引き出しが止まりに当たる、折り目を押さえる、
  紙束を置く、丸めた紙が床に落ちる、バインダーを置く、鍵を回し切る、ガラスの蓋が止まる、
  機械が机に着く。動いている途中でいつ終わるかは分かるので、サーバが教える遅れの分だけ
  早く出し、終わりが**見えた瞬間に聞こえる**ようにします。途中で引き返した動きの分は
  取り消します。動いている間だけ鳴る音（引き出しの滑り、紙が切る空気）は、遅れて
  聞こえ始めても、動きが止まって見える瞬間に終わるよう切ります。
- クリックやキーの音は、押したことが原因なので先回りできません。サーバの遅れの分だけ
  あとに聞こえます。

`DESK_SOUND_DEBUG=1` で、音ごとに「鳴らしてから何 ms で聞こえたか」「狙った瞬間より
何 ms ずれたか」をサーバの時計でログに出します（`DESK_SOUND_TLEN_MS` などでバッファを
変えて試せます）。

> **仮想マシンでは**：VMware の仮想サウンドカード ES1371 と PipeWire の既定の組み合わせでは、
> カードが動いている間ずっと、0.2 秒ごとに空になって再起動します（`pw-top` の ERR が毎秒
> 5〜7 ずつ増える）。これが砂嵐やプチプチのような音になり、遅れも毎回変わります。PipeWire は
> 最後の音から 5 秒はカードを止めないので、DEsk に限らず、何か鳴るたびに数秒続きます。
> カード自体は、バッファを満タンに保てば実時間どおりに読み、空になりません（`aplay` で確認）。
> PipeWire が先に溜めておく量（headroom、VM では 2048 フレーム）が、カードが最初にまとめて
> 読む量より少ないのが原因です。対策はシステムの側で、WirePlumber の規則で headroom を 8192
> にする（下）か、VMware の設定でサウンドカードを HD Audio（`sound.virtualDev = "hdaudio"`）
> にすることです。
>
> ```
> # ~/.config/wireplumber/wireplumber.conf.d/vm-headroom.conf
> monitor.alsa.rules = [
>   { matches = [ { node.name = "~alsa_output.pci.*" } ]
>     actions = { update-props = { api.alsa.headroom = 8192 } } }
> ]
> ```
>
> のあと `systemctl --user restart wireplumber pipewire pipewire-pulse`。開発に使っている VM で
> 試したところ XRUN は 0 になった（カードには常に 6,000〜11,000 フレームが溜まる）。代わりに、
> 鳴らしてから聞こえるまでが約 0.2 秒になる。クリックの音はそのぶん遅れて聞こえ、動きの
> 終わりの音は DEsk がそのぶん早く出して合わせる。

**聞いてみる**：`desk-preview --sounds DIR` で、全部の音（各 1〜4 通り）を WAV に書き出し、
通しで聞ける `all.wav`（約 40 秒）と、何秒目が何の音かの `all.txt` も作ります。

**設定**：Shell Settings の SOUND（`shell.conf` の `sound = off | quiet | normal`、
`letter_sound = yes | no`）。

## 自分で枠を描くアプリも紙に載せる

ヘッダーバーを持つ GTK のアプリ（Firefox、GNOME のアプリ）は、タイトルバーとボタンを
自分で描きます（クライアント側の枠）。以前の DEsk はそういう窓に手を出さず、紙も、右上の折れた角も、影もありません
でした。

いまは**そういう窓も紙に載せます**（既定）。

- アプリの周りに**紙の余白**（上 12 pt、ほか 8 pt）。見出しは刷りません（アプリが自分で
  持っています）。影は紙のもの、右上は**折れた角**で、Fold / Unfold / Discard が使えます。
  折りたたみ・引き出し・捨てる動きも、ほかの窓と同じです
- アプリには「四辺とも並べて置かれている（tiled）」と伝えるので、アプリは自分の影と
  丸い角を描かなくなります。それでも余白に影を描くアプリは、窓の本体で切り取ります
- アプリ自身のボタン（閉じる・最大化など）と見出しはそのまま使えます。角が反応するのは、
  紙の余白の上と折り目そのものだけで、すぐ下にあるアプリの「閉じる」は押せます
- X11 のアプリ（Motif ヒントで枠を断るもの）も同じ。スプラッシュ画面は載せません

**設定**は `$XDG_CONFIG_HOME/desk/shell.conf`（無ければ `~/.config/desk/shell.conf`）。
このファイルは、Shell Settings で初めて何かを変えたときに作られます（自分で作っても
かまいません）。それまでは機械全体の既定（`/etc/xdg/desk/shell.conf`）と、下の既定の
値のままです：

```
paper_for_all_windows = yes      # no にすると、枠を自分で描くアプリはそのまま
paper.firefox-esr = no           # 一つのアプリだけ逆に（desktop id・app id・X のクラス）
```

DEsk はこのファイルを 1 秒ごとに見ていて、変わったらすぐ、開いている窓にも反映します
（窓の本体はその場に置いたまま、紙だけ付け外し）。

### Shell Settings

シェルの設定を変える小さなアプリ **Shell Settings**（`desk-settings`）があります。
ALL APPS の **System** のバインダーに入っています。窓は DEsk の紙（見出しと折れた角は
DEsk のもの）で、その上に描いたフォルダーとメモ帳にフォームが刷ってあります。どれも
変えた瞬間に DEsk に反映されます。

紙はフォルダーのように**二つのタブ**に分かれ、それぞれのポケットに**リング綴じの
メモ帳**が一冊入っています。**Shell**（DEsk 自身の設定、WINDOWS から SOUND まで）と
**System**（機械のほかの部分。NETWORK AND DEVICES から THIS COMPUTER まで、それぞれ
専用のプログラムを開く行）です。

- メモ帳は**節ごとに一枚**。各ページの右の縁には**付箋**が一枚ずつ、ページごとに違う
  高さで貼ってあり、メモ帳から突き出しています（Windows・Desk・Screen…、日本語では
  ウィンドウ・机・画面…と手書き。色は机の付箋と同じ 6 色）
- 付箋を押すと、卓上カレンダーと同じように**ページが上のリングを越えてめくれ**、その
  ページが開きます。間に何枚かあれば少し扇に開いて一緒にめくれ、戻るときは後ろから
  降りてきます。めくったページは後ろに垂れ下がり、その付箋は少し暗く短く、縁の外に
  見えたまま（押せば戻れます）
- タブを替えると、もう一冊のメモ帳がフォルダーの下から引き出されて前の一冊に重なります。
  **開いたときも**、少し置いてからメモ帳が下から引き出されます（どちらも
  `DESK_SLOW` で遅くできます）

  で、入れ子の窓ではホストのポインタなので効きません。Wayland ではコンポジタにしか
  設定できないので、これは DEsk が作る側です
- Control Panel（左奥の機械）とは別のアプリです

`shell.conf` は手で書きます）。ビルドしたまま動かすときは、`build/applications/` の
エントリが ALL APPS に出ます。

## DEsk Experience Index

**DEsk Experience Index**（`desk-index`、ALL APPS と Shell Settings の System タブから）は、
この機械が DEsk の求める仕事をどのくらいこなせるかを、Windows エクスペリエンス
インデックスのように測って点にします。黒い計器盤に真鍮の縁のメーターが五つ並び、
測っている間は針が揺れ、最後に基本スコアのゴム印が押されます。

| 部分 | 何を測るか |
| --- | --- |
| Processor | 部屋のトレーサの計算（SDF の行進）と分岐の多い表引きを、1 スレッドと全スレッドで |
| Memory | 64 MB のコピー（帯域）と 128 MB の追いかけ（遅延）。搭載量（cgroup の上限も）で頭打ち：1.5 GB 未満 1.9、3 GB 未満 2.9、6 GB 未満 4.9、12 GB 未満 6.9 |
| Graphics | 机そのものの 2D の描画（紙の枠と影、フォーム、折りたたみ・丸める動き）を 1440×900 で |
| 3D graphics | GPU で部屋の行進のシェーダ（答えを C と照合し、違えば「wrong」）。ソフトウェア描画（llvmpipe）や GPU 無しは 2.9 まで |
| Disk | 128 MB を書いて（fsync）読み戻す |

- 点は 1.0〜9.9（対数）。3.5 が「2 コア・4 GB の非力なノート」、8.0 が「今の
  デスクトップ」に当たるように合わせてあります。**基本スコアは五つの一番低いもの**で、
  何に足を引っ張られているかも書きます
- 全部で 10〜20 秒。測っている間もウィンドウは動き、Esc や「Stop」で止められます。
  ほかのプログラムが忙しいと、そう注記します
- 結果は `$XDG_STATE_HOME/desk/index.conf` に残り、次に開くと日付と一緒に出ます。
  「Rate again」でもう一度
- 端末から：`desk-index --text`（表を出して保存。コンテナや CI でも）
- `desk-index --suggest`：軽く調べて（2〜3 秒）、この機械に合う Graphics の段階を
  `ultra` / `high` / `medium` / `low` / `2d` で出します（理由は標準エラーに）。インストーラが
  使います（上の「グラフィックの段階」）

## 言語

机の上の言葉（プレート・キー・札・紙片・カレンダー・メモ・Shell Settings・
DEsk Experience Index）と、本棚に並ぶプログラムの名前は、**英語・日本語・中国語（簡体字）・
韓国語・スペイン語・フランス語・ドイツ語**の 7 つから選べます。英語が基本で、訳語は英語を
キーにした表（`src/i18n.c`、Index だけの言葉は `src/index.c`）の、言語ごとの列から引きます
（一語で二通りに訳す語は `clock|DAY` のように文脈を付けます）。訳の無い語は英語のまま出ます。

- `shell.conf` の `language = auto | en | ja | zh | ko | es | fr | de`（Shell Settings の
  Language。選択肢はそれぞれの言語自身の名前で書いてあります）。`auto` はロケール
  （`LC_ALL`・`LC_MESSAGES`・`LANG`）に従い、`ja_…`・`zh_…`・`ko_…`・`es_…`・`fr_…`・`de_…`
  ならその言語、ほかは英語です。
- 変えるとその場で切り替わります。プログラムの名前は .desktop の `Name[<言語>]` を読み直し
  （ロケールが同じ言語ならその地域の名前 `es_MX` などを先に、違えば `zh_CN`・`ko_KR`・
  `es_ES`・`fr_FR`・`de_DE`）、絵は全部描き直します。
- カレンダーは売っている国のものの書き方です。月と曜日の名前（`OKTOBER`・`SAMEDI`・
  `星期六`・`토요일`…）、年月の並び（`2026年10月`・`2026년 10월`・`OCTUBRE 2026`）、
  週の範囲（`4. – 10. OKT 2026`・`2026년 10월 4일 – 10일`）。時計の DATE は中国語・韓国語で
  `2026/10/10`、スペイン語・フランス語・ドイツ語で `10/OCT/2026`（14 セグメントで書ける
  文字だけ）。Index の日付と午前・午後も言語ごとです。
- 漢字は中国・日本・韓国で字形が違うので、中国語なら Noto CJK **SC**、韓国語なら **KR** の
  書体で書きます（日本でしか使わない書体は日本語のときだけ。Klee One は英字にだけ使います）。
- 行は、英語などは単語の間、日本語・中国語はどこでも、韓国語は**単語の間（分かち書き）で**
  折り返します。フランス語の「 ;」「 :」などの前は改行しない空白にしてあります。
- 収まらない言葉は少し小さく刷ります（カレンダーのタブ `SEMAINE`、バインダーの札
  `Développement`、手紙の本文、Control Panel の `SANS RÉTROÉCLAIRAGE`）。

## 標準のプログラム

DEsk は GNOME や KDE のように**一揃いのデスクトップ**として使えるように、役目ごとの
標準のプログラムを決めています。引き出しの小物と Super+Enter はこれを開きます。

| 役目 | 標準（入っている最初のもの） |
| --- | --- |
| 端末 | Xfce Terminal → MATE Terminal → LXTerminal → Terminator → Konsole ほか |
| ブラウザ | Firefox ESR → Firefox（Ubuntu の snap も）→ Chromium ほか |
| ファイル | Thunar → Caja → PCManFM → Nemo → PCManFM-Qt → Dolphin → Nautilus |
| エディタ | Mousepad → Pluma → FeatherPad → KWrite → Kate ほか |

決め方は上から順に:

1. `shell.conf` の `app.terminal` / `app.browser` / `app.files` / `app.editor`
   （.desktop の id。例 `app.editor = pluma.desktop`）。端末は Shell Settings の
   System →「Look and language」の **Terminal** でも選べます（入っている端末が名前で
   並びます。Automatic＝`auto` は下の順のまま）
2. freedesktop.org の順の既定アプリの表：`~/.config/desk-mimeapps.list`（DEsk の
   中だけ）、`~/.config/mimeapps.list`（Shell Settings の「Default programs」＝
   xfce4-mime-settings が書くもの）、同じ二つを `$XDG_CONFIG_DIRS`、
   `~/.local/share/applications`、`$XDG_DATA_DIRS` の `applications/` の順に。
   インストールすると DEsk の既定のもの（`desk-mimeapps.list`）が
   `/usr/local/share/applications/` に入ります。役目は MIME 型で引きます（ブラウザは
   `x-scheme-handler/https`、ファイルは `inode/directory`、エディタは `text/plain`）。
   xdg-open・GIO と同じ答えになります（GIO と同じく [Added Associations] と
   [Removed Associations] は既定には使いません）
3. 上の表の順で、入っているもの
4. それも無ければ Categories で（開発用のものは後回し）

端末を要るアプリ（`Terminal=true`）は、標準の端末の中で開きます（Xfce Terminal・
MATE Terminal・Terminator は `-x`、LXTerminal と Konsole は `-e`）。ほかのデスクトップ
専用の項目（`OnlyShowIn=MATE` の Caja など）や `NoDisplay` の項目は本棚に出ませんが、
id で名指しすれば開けます（標準・既定アプリ・shell.conf）。`shelves.conf` で棚に置く
こともできます（`caja-browser.desktop = Utilities`）。以前の版の
`drawer` ファイルにあったエディタなど（`app cursor.desktop` のような行）は、初回に
標準の役目へ置き換えます（ログに一行出ます）。

## 書体

cairo の簡易フォント API は一つの書体からしか字を取らず、足りない字を他の書体で
補いません。そこで役ごとに**欧文の書体と和文の書体**を決めておき、文字列ごとに、
欧文の書体が全部の字を持っていればそれ、無ければ和文の書体で描きます（`src/fonts.c`）。

| 役 | 欧文 | 和文 |
| --- | --- | --- |
| 本・カレンダーの見出し | P052（Palatino） | Noto Serif CJK JP |
| 刻印（プレート・計器・札） | Nimbus Sans（Helvetica） | Noto Sans CJK JP |
| タイプ（手紙・ラベル） | Nimbus Mono PS（Courier） | Noto Sans Mono CJK JP |
| 印刷（本文） | Noto Serif CJK JP | 同左 |
| 画面（ブラウン管） | DejaVu Sans Mono | Noto Sans Mono CJK JP |
| 手書き（メモ） | Klee One | Klee One |

どれも無ければ、表の後ろに続く候補（TeX Gyre、Liberation、DejaVu など）から入って
いるものを使います。選ばれた書体は起動時のログに一行出ます。

## 困ったとき

DEsk の机の部品（引き出し・本棚・Control Panel・ポスト・カレンダーなど）がおかしな
状態から戻らなくなったときのために:

- **Ctrl+Alt+Del を 2 回**（0.8 秒以内に続けて）：机を立て直します。手に持っている物を
  放し、開いている物（引き出し・本棚・Control Panel・ポスト・カレンダー・メモ・
  バインダー）をしまい、描き置きの絵を全部描き直して机を並べ直し、`shell.conf` を
  読み直し、キーボードとポインタを設定し直します。**窓（アプリ）はそのまま**、ロック中
  ならロックのままです（玄関のドアを描き直すだけ）。
- **Ctrl+Alt+Del を 3 回**：ログアウトします（LOG OUT と同じく、窓に閉じるよう頼んで
  から。保存していない窓が止めたら、もう一度 3 回押せば進みます）。玄関の前でも効きます。
- 端末や別の VT（Ctrl+Alt+F3 で同じユーザーでログイン）から **`desk-ctl`** でも同じこと
  ができます：`desk-ctl reset`（2 回と同じ）、`desk-ctl logout`（3 回と同じ）、
  `desk-ctl logout --now`（すぐに終える。窓が保存していないものは失われます。机のメモと
  カレンダーは残ります）。DEsk のプロセス番号は `$XDG_RUNTIME_DIR/desk.lock` に書いて
  あります。
- Ctrl+Alt+Del は窓には渡しません。VMware などの仮想マシンでは、ホストが Ctrl+Alt+Del を
  取ってしまうので、Ctrl+Alt+Insert（VMware）などゲストに送るキーを使ってください。

### 不具合を知らせるとき

一番簡単なのは、端末で次を実行して、できたファイル `~/desk-report.txt` を添えることです（どのデスクトップからでも、コンソールからでも。DEsk が起動しなくても使えます）。

```sh
desk-report
```

DEsk の版、Linux、グラフィックカードとそのドライバーとつながった画面、直前のセッションのログ、DEsk が落ちたかどうかをまとめ、ユーザー名・ホームフォルダ・マシン名・ネットワークのアドレスは取り除きます。送る前に中身を見てください。何をして何が起きたかも書いてください。

これが無いとき（古い DEsk や、インストールされていないとき）は、次を手で添えてください。

- `~/.local/state/desk/session.log`（ひとつ前のセッションのことなら `session.log.old` も）— DEsk が動きながら言ったこと
- インストーラが止まったなら、端末に出た最後の数行（`install_session.sh` から走らせたときは `~/.local/state/desk/install.log`）

どちらもただのテキストです。送る前に中身を見てください。

## Docker で検証

GPU は不要です。headless + pixman でコンポジタを起動し、同じ描画パスで PNG を書き出します。
検証時には本物の Wayland クライアント（`foot`）がソケットに接続します。

```sh
chmod +x scripts/verify.sh scripts/entrypoint.sh
./scripts/verify.sh
```

Dockerfile は木全体をコピーし（`.dockerignore` が `build*`・`out`・`.git` を除く）、
ビルドの段で `scripts/install_debian.sh --yes --bare --prefix /usr` を走らせるので、
パッケージの一覧はインストーラとずれません。部屋のキャッシュは `/tmp/desk-cache` に
置き、一度焼いた部屋をプレビューとデスクトップで使い回します。

`out/preview.png` と `out/desktop.png` ができます。
`--screenshot` は wlr-screencopy 経由で `grim` に撮らせるので、クライアントのウィンドウや
影を含む**実際のコンポジタ出力**が保存されます（`grim` が無い場合は壁紙のみの描き起こしに
フォールバック）。`--dump` は従来どおり cairo でデスクトップを描いた絵です。macOS では Colima 経由の Docker で動きます。

## コマンドライン

```
desk --version                          # どの版か（desk-settings・desk-index も同じ）
desk --headless --size 1600x1000 --dump chrome.png --screenshot desk.png --delay 4000 -s foot

desk-preview -o console.png -s 1440x900 --console

```
